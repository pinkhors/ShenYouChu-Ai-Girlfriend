## 1. 架构总览

采用**适度微服务**：服务边界从第一天明确，部署单元保持精简。不是每个 Agent 一个服务。

```text
┌────────────────────────────────────────────┐
│ Desktop（Electron + React + TypeScript）    │
│ 采集/播放、对话 UI、字幕、打断、Live2D(P2)  │
└──────┬──────────────────────────┬──────────┘
       │ HTTPS / WSS              │ WebRTC 媒体
       ▼                          ▼
┌──────────────────┐   ┌──────────────────────────┐
│ Gateway/Identity │   │ Media & Vision Service   │
│ 认证、入口、凭证 │   │ WebRTC 接入（选型待 POC）│
│ 初期与 Core 同包 │   │ Python + MediaPipe 分析  │
└────────┬─────────┘   │ 录像归档任务             │
         │             └───────────┬──────────────┘
         ▼                         │ 结构化 VisualSignal
┌──────────────────────────────┐   │
│ Core Conversation Service    │◄──┘
│（Spring Boot + Java 17）      │
│ 人设/会话/Turn 状态机         │
│ Agent 编排（Graph 按需）      │
│ 记忆检索与异步整理            │
│ 模型适配层（LLM/ASR/TTS/嵌入）│
│ 活动事件记录                  │
└──────┬───────────────────────┘
       ▼
┌────────────────────────────────────────────┐
│ MySQL │ Redis │ Milvus │ S3 对象存储       │
└────────────────────────────────────────────┘
       │
       ▼
云模型 API（首选）或自托管模型服务（P2）
```

### 1.1 部署单元

| 单元 | 技术 | 拆分理由 |
|---|---|---|
| Desktop | Electron + React + TypeScript | 桌面采集与交互，不持有任何后端密钥 |
| Gateway/Identity | Spring Boot 模块 | 认证与凭证签发；初期与 Core 同进程，接口独立 |
| Core Conversation | Spring Boot + Java 17 | 对话、记忆、编排、模型适配 |
| Media & Vision | WebRTC 服务 + Python worker | 技术栈与资源模型不同，可独立扩容/GPU |
| Infra | MySQL/Redis/Milvus/对象存储（S3 兼容） | 通过 Compose 本地启动，接口不因环境变化 |

### 1.2 选型理由

- **Electron + React + TypeScript**：桌面端调用摄像头/麦克风方便；React 生态成熟，便于吸引全球开源贡献者。该决定见 [ADR-0001](./adr/0001-frontend-react.md)；Vue3 因全球生态与协作面较窄未采用。
- **Spring Boot + Spring AI Alibaba**：与 PRD 技术栈一致，Graph 支持并行与流式；但首版不依赖复杂 DAG，先用显式编排，出现真实并行收益时再引入。运行基线为 Java 17（当前开发环境），需要 21 特性时再统一升级。
- **MyBatis-Plus（Spring Boot 3.x）**：统一持久化方案，提供条件分页、逻辑删除与乐观锁；用户归属条件必须显式书写，租户插件不作为授权依据。决策见 [ADR-0003](./adr/0003-mybatis-plus-persistence.md)。
- **MySQL**：权威事实存储，事务成熟。
- **Redis**：会话实时状态与限流缓存，全部带 TTL；不作为权威事实源。
- **Milvus**：长期记忆语义检索；P0 可先不启用，接口预留。
- **S3 兼容对象存储**：录像与对象文件私有存储；本地开发用 RustFS（MinIO 已停止分发免费镜像，见 [ADR-0004](./adr/0004-local-object-storage-rustfs.md)），生产可选 MinIO、RustFS 或云 OSS/S3。
- **WebRTC 媒体服务**：负责实时音视频传输与录像，**不自研 SFU**；候选在 POC 后确定。
- **Python + MediaPipe**：视觉推理生态与 Java 解耦，可独立部署/扩容。

### 1.3 明确不采用

- 不为每个 Agent 建独立服务或独立数据库；
- 不用对象存储承担实时传输；
- 不用轮询数据库实现实时对话；
- 不在首版引入 Kafka/K8s/服务网格；
- 不把"提前生成、记忆回来再改"作为默认链路（已否决）。

## 2. 模块划分

### 2.1 Core Conversation 内部模块

| 模块 | 接口职责（对外小而稳） |
|---|---|
| Conversation | 创建/查询会话，管理消息与轮次 |
| Turn Orchestrator | 驱动 turn 状态机，统一取消与超时 |
| Persona | 加载人设与提示词组装 |
| Memory | 记忆写入、召回、纠正、删除；含异步整理任务 |
| Model Adapter | LLM/ASR/TTS/Embedding 统一接口与供应商实现 |
| Activity | 活动事件写入与查询 |
| Search | 全局搜索 seam；P1 MySQL FULLTEXT，后续可替换 OpenSearch；含运营检索授权与审计 |
| Identity | 认证、凭证、当前用户上下文（初期同进程） |
| Media Token | 为媒体会话签发短时凭证，校验归属 |

设计原则：**深模块、小接口**。调用方只依赖接口，不依赖具体供应商或表结构；接口是唯一测试面。

### 2.2 Media & Vision 模块

- Media Gateway：房间生命周期、凭证校验、轨道管理；
- Recorder：按录制授权异步归档到 对象存储（S3 兼容）；
- Vision Worker：解码 → MediaPipe → 时序融合 → VisualSignal 发布；
- Signal Publisher：2Hz 快照 + 状态变化事件，经内部通道发往 Core。

视觉热路径不经过 Spring 请求线程，避免高频调用拖垮对话服务。

## 3. 核心链路设计

### 3.1 语音对话（P0）

```text
按住说话 → 音频分片上行（WSS 二进制）
        → ASR partial → 仅字幕（不触发回答）
松开    → ASR final
        → Turn Orchestrator 冻结输入与记忆快照
        → LLM 流式生成 → 按句边界送入 TTS → 音频块下发 → 客户端顺序播放
        → 完成后异步：记忆整理 + 活动事件
打断    → turnId 取消广播至 ASR/LLM/TTS/播放/媒体
```

关键约束：

- **门闩**：`final transcript + 不可变记忆快照` 是 LLM 启动条件；
- **不可撤回**：已提交给用户的文本/音频只允许继续后缀，不允许回改语义；
- **取消即丢弃**：所有消息带 turnId 与 sequence，旧 turn 的消息一律丢弃；
- **句子级 TTS**：不逐 token 合成；TTS 失败降级为纯文本。

### 3.2 视频与视觉（P1）

```text
客户端摄像头 → WebRTC → Media Gateway
                      ├→ 解码取最新帧（丢弃过期帧）→ MediaPipe
                      │    → 时序平滑/迟滞 → VisualSignal（2Hz + 变化事件）
                      │    → 注入下一轮对话上下文
                      └→ 授权录制 → 分段 → 封装 → 对象存储（S3 兼容） → 元数据入库
```

视觉信号字段、置信度与 unknown 规则见契约文档。**低置信度不入提示词**；信号带 `captureTs/inferenceEndTs/emitTs`，便于判断新鲜度与延迟。

### 3.3 Turn 状态机

```text
idle → listening → transcribing → retrieving → generating → speaking → completed
                        └──────────── cancelled ←────────────┘
任意状态 → failed（可降级）
```

状态机是取消、超时与幂等的唯一权威；客户端不得自行推导服务端状态。

### 3.4 搜索链路

```text
写入路径：MySQL 权威数据 → outbox 事件 → Indexer → 搜索索引（可重建）
查询路径：SearchPort → 用户搜索（强制本人范围）
                    └→ 运营检索（角色 + 事由 + 脱敏 + 审计，见 ADR-0002）

删除路径：删除事件（高优先级）→ 索引移除；查询命中后回源校验未删除
```

- P1 用 MySQL FULLTEXT/ngram，满足"能搜到自己的记录"；出现相关性排序、中文分词、高亮、跨实体统一排序或性能不足时再引入 OpenSearch；
- OpenSearch 若引入，作为 Compose 可选 `search` profile，不作为默认启动依赖；
- 搜索索引始终是派生数据：可清空重建，不影响 MySQL 权威数据；
- 索引文档必须带 `userId`，查询在索引层强制过滤；运营检索的范围由服务端授权决定。

## 4. 数据模型概览

详细字段、索引与迁移规范见[数据与接口契约](./contracts/data-and-interface-contracts.md)。

核心实体：`users`、`characters`、`user_character_states`、`conversations`、`messages`、`memories`、`media_sessions`、`recordings`、`visual_events`、`activity_events`、`deletion_jobs`。

统一约定：

- 主键 UUID 字符串；所有业务表 `created_at / updated_at / deleted_at`；事件类另加 `occurred_at`；
- 时间统一 UTC 存储（`DATETIME(3)`），前端本地展示；
- 归属字段 `user_id` 不可为空（系统模板表除外），查询必须带归属条件；
- 逻辑删除用于常规业务隐藏；用户主动"清除"走 `deletion_jobs` 物理级联删除；
- 审计字段由应用写入，保证时区与可测试性一致。

## 5. 接口设计原则

- REST 前缀 `/api/v1`，资源路径不携带"当前用户"，身份来自认证上下文；
- 实时双向链路（对话、音频、事件）用 WebSocket；媒体用 WebRTC；
- 所有写操作支持 `Idempotency-Key`，错误体含 `code/message/requestId`；
- 分页用 cursor，不用 offset 深翻页；
- 跨服务调用只传 ID 与必要字段，接收方重新校验归属；
- 契约变更需版本化并通过契约测试。详见契约文档。

## 6. 模型适配与选型

模型全部通过适配器接口调用，配置化切换：

| 能力 | 首选（云 API） | 备选 | 备注 |
|---|---|---|---|
| ASR | `paraformer-realtime-v2` | FunASR 流式自托管 | 区分 partial/final |
| LLM | `qwen3.7-plus` | `qwen3.7-flash`（延迟对比）；自托管 Qwen Instruct | 同账号实测后定 |
| TTS | `cosyvoice-v3-flash` | CosyVoice 自托管 | 音色需授权 |
| Embedding | `text-embedding-v4` | BGE-M3 自托管 | 维度变更需重建索引 |
| 视觉 | MediaPipe Face/Pose/Hand | 自训练表情分类器 | 不引入逐帧多模态大模型 |

选择理由与边界：

- 首版用云 API：无需 GPU 运维，先验证体验与延迟；
- 自托管作为 P2，通过同一接口替换，不重写业务；
- **不承诺**官方宣传延迟直接等于本项目链路延迟，必须实测；
- 模型 ID 以账号可用性为准，集中配置，禁止散落硬编码。

## 7. 关键技术难点与对策

| 难点 | 风险 | 对策 |
|---|---|---|
| 首音延迟 | 链路叠加、云波动 | 分句流式 TTS、连接复用、预热、分阶段埋点，先测再优化 |
| 打断与迟到消息 | 旧音频串入新一轮 | turnId+sequence 全链路、取消广播、客户端丢弃旧序号 |
| ASR 中间稿不稳定 | 语义前后矛盾 | 中间稿只做字幕；最终稿才触发回答（已定） |
| 视觉误判 | "读懂心理"过度承诺 | 只输出表情估计+置信度，低置信度 unknown，措辞不确定 |
| 多人隔离 | 越权、串线 | 服务端身份、全存储归属、隔离测试门禁 |
| 搜索越权 | 一条查询泄露全部用户数据 | 索引层强制 userId 过滤、运营检索四重约束、隔离测试阻断发布 |
| 视频归档 | 阻塞实时、磁盘增长 | 异步分段归档、保留期、容量监控、独立磁盘 |
| 服务拆分裂化 | 本地调试困难 | 少量部署单元、接口先行、Compose Profile 按需启动 |
| 模型供应商变更 | 接口漂移 | 适配器+契约测试+配置化模型 ID |

### 替代方案（风险触发时）

- 首音延迟不达标：缩短首句、减少上下文、检索硬超时、换 flash 模型、就近地域；**不启用回改式投机生成**；
- 视觉 FPS 不足：降低输入分辨率/频率、按需启用人脸或姿态、独立进程/降采样；
- Milvus 运维复杂：记忆量小时先用 MySQL 结构化检索，向量检索延后；
- 媒体自建成本高：优先成熟自托管方案，必要时先用纯语音上线。

## 8. 性能与可扩展性

- **无状态优先**：Core 与 Vision 尽量无状态，状态集中 Redis/DB，便于横向扩容；
- **背压与丢弃**：视觉只保最新帧；实时通道有界队列，满则丢弃旧数据而非堆积；
- **超时与降级**：记忆检索 500ms、模型调用分档超时，超时走降级路径；
- **资源隔离**：视频解码/推理与对话线程分离；GPU 模型按需独立部署；
- **容量演进**：并发增加先加无状态实例；存储增长先扩 对象存储（S3 兼容）；检索压力再拆 Milvus 策略；
- **不提前优化**：以实测瓶颈决定扩容对象。

## 9. 安全与隐私

- **密钥**：只存服务端环境变量/密钥管理，前端零密钥；日志与错误体不回显密钥；
- **认证**：短时凭证；媒体与文件凭证服务端签发并限定资源；
- **存储**：对象存储（S3 兼容） 私有桶、短期签名 URL、对象 Key 不构成授权；
- **数据最小化**：不存原始关键点；活动事件引用正文而非复制；
- **删除**：`deletion_jobs` 驱动 MySQL/Redis/Milvus/对象存储（S3 兼容）/任务级联，保留最小删除审计；
- **日志**：不记录完整对话正文、音频、视频帧与凭证；traceId 关联而非内容复制；
- **搜索**：索引继承数据隐私级别；用户查询强制本人范围；运营检索必须带事由、默认脱敏并写入 `admin.search.performed` 审计（ADR-0002）；
- **开源**：`.env.example` 占位，真实密钥与测试媒体禁止入库。

## 10. 测试与发布策略

### 10.1 测试分层

| 层级 | 范围 | 门禁 |
|---|---|---|
| 单元 | 领域逻辑、状态机、适配器映射 | PR 必过 |
| 契约 | 模型适配器、REST/WS 事件 schema | PR 必过 |
| 集成 | DB/缓存/对象存储/向量 + 服务 | 主分支必过 |
| 端到端 | 登录→对话→语音→取消→删除 | 发布前必过 |
| 隔离安全 | A/B 跨用户访问矩阵、搜索越权、运营审计完整性 | 发布门禁（阻断） |
| 性能 | 首音延迟、视觉 FPS、并发容量 | 里程碑实测，报告归档 |
| 故障演练 | 模型超时、媒体断开、存储不可用 | 里程碑执行 |

### 10.2 发布策略

- 环境：local（Compose）→ staging → production；
- 镜像版本化，配置外置；数据库迁移在发布流程中自动执行且可回滚；
- 发布前跑端到端与隔离测试；发布后观察延迟与错误率，异常回滚上一镜像；
- 首版单机 Compose 即可；扩容与高可用待容量目标确认后再引入编排平台。

## 11. 分阶段开发计划

### 阶段 0：地基（对应 M0）

交付：Monorepo 结构、Compose 基础设施、认证与用户隔离、数据库迁移、CI、健康检查。
出口：两个用户互不可见；一键启动文档可用。

### 阶段 1：文本伴侣（M1）

交付：人设、流式对话、关系状态、最近对话记忆、记忆页、活动记录页、设置页、用户全局搜索（MySQL FULLTEXT）。
出口：PRD 中 P0 文本与隐私需求及 FR-8.1～8.4 验收通过。

### 阶段 2：语音伴侣（M2）

交付：音频上行、ASR partial/final、分句流式 TTS、打断取消、降级、延迟埋点。
出口：完成首音延迟实测报告（P50/P95/P99，冷启动单列）。

### 阶段 3：视频伴侣（M3）

交付：媒体服务 POC 与集成、视觉信号、信号注入、授权录像、录像页。
出口：视觉 FPS 与信号稳定性实测；跨用户媒体/文件隔离测试通过。

### 阶段 4：开源就绪（M4）

交付：README、部署文档、`.env.example`、隔离测试套件、许可证检查、贡献指南。
出口：新机器 30 分钟内跑通。

### 阶段 5：增强（P2）

运营检索（角色权限、脱敏、审计测试完成后上线）、语义记忆、记忆纠正、Live2D、模型自托管，按实测价值排序。

## 12. 主要风险登记

| 风险 | 影响 | 触发信号 | 替代方案 |
|---|---|---|---|
| 云模型延迟/限流 | 首音不达标 | P95 超目标 | 换 flash/就近地域/自托管 |
| 视觉准确率不达标 | 体验失真 | 抽检误判多 | 降级为粗粒度信号，只在高置信度使用 |
| 媒体选型不合适 | 工期与稳定性 | POC 不稳定 | 换成熟方案或先语音上线 |
| 隔离缺陷 | 严重信任问题 | 安全测试失败 | 阻断发布，修复合入回归 |
| 范围膨胀 | 长期不可交付 | 里程碑延期 | 以 PRD 非目标为准，P2 延后 |
| 存储与带宽成本 | 运营成本 | 录像增长快 | 保留期、压缩、按需录制 |
| 素材与音色版权 | 开源合规 | 无法确认授权 | 替换为可商用素材后再发布 |

## 13. 待确认项

与 PRD 待确认项一致，技术侧补充：

| 编号 | 问题 | 默认建议 |
