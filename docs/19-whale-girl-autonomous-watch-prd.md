## 1. 背景与目标

### 1.1 背景

当前产品已有：一对一唯一会话、角色自定义、文本对话与 SSE、记忆列表与星图、关系状态、主动消息策略（8 级门槛）、LLM BYOK。
但（见 `docs/18`）：

1. **记忆删除不闭环**——用户删除的记忆仍可能被召回，这是本功能的前置阻塞（`⛓`）；
2. **Token 从未计量**——`messages.token_count` 列存在但从不写入，而"她独立刷视频"必须以成本上限为前提；
3. **主动消息只能手动触发**——已有策略但没有话题来源与调度；
4. **产品缺少"她不在你身边时也在生活"的可信度**。

本功能要解决的核心问题：**让角色拥有独立的、可被观察的、能回流到对话的"生活"**。

### 1.2 目标（按优先级）

1. **可观测**：用户能看到她今天做了什么、花了多少、在哪活跃（§6 行为面板）；
2. **可回流**：她的行为能沉淀为记忆，并成为她主动找你的**唯一**话题来源（§5.7）；
3. **可信**：每一条数字、每一句引用都能追到证据链（视频 → 层 → 片段 → 时间）；
4. **可控**：日预算硬顶、深读比例上限、一键停用。

### 1.3 一句话定义

> 她有自己的内容池与刷视频节奏；她的每一次浏览都留痕、少量进记忆、多数进统计；面板把这些变成你能看见的证据，并决定她今天拿什么来找你聊天。

### 1.4 与现有产品的关系

- 本功能**不改变**「每个 `(user, character)` 只有一条会话」的核心模型；
- 本功能**不新增**会话，只新增行为流与面板；
- 她的行为**默认只读**；写操作（评论/回复）走 §5.9 的三级安全路径。

## 2. 术语（本文新增）

| 术语 | 定义 | 避免说法 |
|---|---|---|
| **Watch Session（观看会话）** | 一次连续的内容消费过程（含 ≥1 条内容），有开始/结束时间与预算归属 | 刷单、任务 |
| **Watch Event（行为事件）** | 她的一个原子动作（浏览/看评论/翻浏览记录/评论/回复/划过），见 §5.3 | 日志（日志≠事件） |
| **Content Item（内容项）** | 一条待理解的内容，含平台、`videoRef`、公开元数据 | 视频（可能是图文） |
| **Co-watch（陪看）** | 用户在看、她在旁边一起看并给反应 | 代刷 |
| **Autonomous Watch（自主浏览）** | 她在自己的内容池里按节奏浏览，无需用户在场 | 自动刷单 |
| **Behavior Panel（行为面板）** | 展示行为记录、统计、Token 与"可聊候选"的界面 | 报表、BI |
| **Candidate Topic（可聊候选）** | 从行为中提炼的、可用于主动消息的具体话题 | 摘要 |
| **Evidence Chain（证据链）** | 内容 → 走了哪些理解层 → 片段 → 时间 → 平台回执 | — |
| **Content Pool（内容池）** | 按人设策展、与用户账号隔离的内容来源集合 | 推荐流 |
| **Whale Girl（鲸鱼娘）** | 本功能的角色主体；能力与具体角色解耦（见 Q-1） | 官方角色（两者不是同一概念） |

## 3. 范围

### 3.1 范围内

| 能力 | 优先级 | 说明 |
|---|---|---|
| 陪看（悬浮窗 + 反应层级） | P0 | §5.1 |
| 自主浏览（内容池 + 节奏 + 预算） | P0 | §5.2 |
| 行为记录（事件表 + 三类动作区分） | P0 | §5.3 |
| 行为面板（五层信息 + 明细 + 下钻） | P0 | §5.4、§6 |
| 内容理解流水线（评论 → 字幕 → OCR） | P0 | §5.5、§9.0 |
| 记忆沉淀与召回 | P0 `⛓` | §5.6 |
| 主动消息闭环（候选 → 发出） | P1 | §5.7 |
| Token 计量与预算 | P0 `⛓` | §5.8 |
| 安全与隐私（写操作、PII、可见指示） | P0 | §5.9 |
| 平台适配器（沙盒 / 抖音只读 / B站只读） | P1 | §5.10 |

### 3.2 非目标（明确不做）

- **不做**自动化评论/回复到真实公开平台（见 §9 风险 R-01）；
- **不做**页面抓取、逆向接口、模拟登录；
- **不做**私信、@ 作者、与他人建立社交关系；
- **不做**内容推荐给用户（她是陪伴者，不是推荐算法）；
- **不做**她"替你看完给总结"（这是**陪伴**，不是**代劳**）；
- **不做**多角色同场、视频通话、Live2D（与 `docs/02` M3 一并移出路线，见 §3.3 与 §11.2）。

### 3.3 路线修订（本次对话的结论，需评审确认）

原路线按"技术层"切（M0 地基 → M1 文本 → M2 语音 → M3 视频），导致每个模态都只做一半、且没有任何一期能"完整一个闭环"。建议改为按"闭环"切：

| 期 | 目标 | 出口判据 | 工期 |
|---|---|---|---|
| **A 闭环期** | 她记得、找得到、会主动 | 删掉的记忆进不了 prompt；能搜到 3 个月前一句话；重开应用能看到"她找过你" | 2–3 周 |
| **B 交付期** | 能装、能更新、敢给别人 | 安装包可分发；注册脚本刷不出额度；登出后本机无 Key | 2 周 |
| **C 声音期** | 2 秒内出声、能插嘴 | 首音 P95 < 2s；她说话时用户开口 500ms 内停 | 3–4 周 |
| **D 留存期**（本文所属） | 有"想回来看看"的理由 | 面板被真实打开；主动消息有话题来源；次日留存 | 持续 |

**移出路线**：视频与视觉信号、录像与媒体会话（原 M3）、Live2D、运营检索后台、声音克隆与唱句（`docs/14/15` 保留为待评审档案，不进排期）。

> 该修订与 `docs/01` §4.5（FR-5 视频，P1）与 `docs/02` M3 存在冲突，按 `docs/03` 需补 ADR 裁决（Q-2）。

## 4. 用户与核心场景

**目标用户**：希望"她有自己的生活"的独居青年；不接受"她只在我说话时才存在"的陪伴体验。

| # | 场景 | 用户行为 | 系统行为 | 优先级 |
|---|---|---|---|---|
| S1 | 陪看 | 点「一起刷」，把视频链接拖给她 | 贴边悬浮，按反应层级给表情与极短气泡 | P0 |
| S2 | 独立浏览 | 打开应用（或到点自动） | 她在内容池里看 5–15 条，留痕 | P0 |
| S3 | 查岗式好奇 | 打开行为面板 | 五层信息 + 明细 + 证据链 | P0 |
| S4 | 话题回流 | 面板底部点「让她说」 | 生成主动消息，带上具体细节 | P1 |
| S5 | 被召回 | 聊天里提"你昨天看的那个…" | 语义召回并引用细节，允许记错 | P0 `⛓` |
| S6 | 失望与纠正 | 点「别提这个」/删除记忆 | 负向偏好 7 天生效；记忆删除真生效 | P0 `⛓` |

## 5. 功能需求

### 5.1 陪看（FR-W.1，P0）

**三种呈现形态**（同一状态，三种展开级别）：

| 形态 | 规格 | 用途 |
|---|---|---|
| **贴边悬浮**（默认） | 220×300，无边框、透明底、`alwaysOnTop`、可穿透点击、吸附屏幕边缘、记住上次位置 | 正常刷内容时她在旁边存在 |
| **并排面板** | 内容区 + 她 380px | 边看边聊 |
| **共同观看** | 内容缩至右下，她占主体 | 睡前/专门陪她看 |

**入口**（四类）：

1. 聊天页顶部「一起刷」（与"让她先开口 / 通话"并列）；
2. 全局快捷键 `Ctrl+Shift+W` 唤起/收起；
3. 托盘菜单「叫她来一起看」；
4. （可选、须 opt-in）检测到内容窗口在前台时，她轻敲窗口边缘一次，可永久关闭。

**她怎么"看到"内容**（三级，按阶段启用）：

| 方案 | 做法 | 阶段 | 约束 |
|---|---|---|---|
| A 分享/拖入链接（或文件） | 用户把链接/视频拖进她的窗口 | **MVP** | 完全合规、信号最干净 |
| B 屏幕区域授权 | 用户框选区域，本地抽帧 + OCR/ASR | V2 | 帧**不出本机**、常驻可见指示、一键暂停 |
| C 平台开放 API | 官方授权取元数据 | 待资质 | 不阻塞 |

**验收**：
- 悬浮窗可穿透点击、Esc 收起、检测全屏时自动隐藏、不遮挡字幕；
- 拖入链接后 ≤2s 出现"她在看"状态；
- 关闭应用后本机不残留采集帧（临时目录为空）。

### 5.2 自主浏览（FR-W.2，P0）

- **内容池**：按人设策展（海洋/治愈/赶海/萌宠/手工/音乐）70–80%，探索 10–20%，黑名单 100% 拦截；
- **节奏**：每日 1–3 个观看会话，单会话 5–15 条，夜间配额减半；
- **不追热点**：热点内容不入池（防人设漂移）；
- **可停用**：一键暂停（暂停后不再产生任何事件与开销），状态在面板明示。

**验收**：
- 停用后 24h 内新增事件数 = 0，Token 消耗 = 0；
- 内容池与用户账号的推荐流**无交集**（独立凭据/独立池）。

### 5.3 行为记录（FR-W.3，P0）

**每个动作一条事件**，字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `eventId / characterId / platform` | ✓ | `platform ∈ douyin / bilibili / sandbox` |
| `action` | ✓ | `browse`（浏览）/ `view_comments`（**仅看评论**）/ `view_history`（**仅查看浏览记录**）/ `comment` / `reply` / `skip`（<3s 划过） |
| `contentRef` | ✓ | `videoId / 标题 / 作者公开名 / topic / 封面` |
| `result` | ✓ | `success / failed / pending_confirm`（评论类必须有失败态） |
| `durationMs / occurredAt` | ✓ | 停留时长与本地时区时间戳 |
| `tokenIn / tokenOut / costUsd` | ✓（可 0） | 归因到该动作 |
| `evidenceLevel` | ✓ | `comments / subtitle / asr / ocr / cover` |
| `memoryId` | 可空 | 反向链接记忆 |
| `sessionId` | ✓ | 归属观看会话 |

**动作语义必须区分**（这是面板四类筛选的来源）：

- `view_comments`：只翻了评论区，**没有**看内容本身；
- `view_history`：翻的是**她自己**的浏览历史（不是别人的）；
- 两者的统计口径与 `browse` **分开计数**，不合并进"浏览视频数"。

**验收**：
- 四类动作各自可查、可筛、计数互不污染；
- 评论失败必须落 `failed` 并带原因码，不得静默丢弃。

### 5.4 行为面板（FR-W.4，P0）

#### 5.4.1 指标口径（先定义，再实现）

| 指标 | 定义 | 常见错误 |
|---|---|---|
| 浏览视频数 | `count(distinct contentRef)` 且 `action=browse` | 同一条反复刷重复计数 |
| 评论数 | `action=comment AND result=success` | 把失败算进去导致虚高 |
| 回复数 | `action=reply AND result=success` | 与 `pending_confirm` 混算 |
| 评论率 | 评论数 / 浏览数（健康区间 2–8%） | >15% 像水军 |
| Token 总消耗 | `sum(tokenIn+tokenOut)`，**embedding 单列** | 把记忆整理混进对话成本 |
| 今日 | 本地时区当日 00:00 起，跨午夜按 `occurredAt` 归属 | 用 UTC 导致差 8 小时 |

#### 5.4.2 时间范围

**今日 / 本周 / 本月**（`本周` 按周一 00:00 起；`本月` 按 1 日 00:00 起）。切换范围为**全局筛选**，L0–L5 全部联动。

#### 5.4.3 必须展示的内容

| 区块 | 内容 | 层级 |
|---|---|---|
| 一句话摘要 | 她的语气（"今天看了 14 个视频，关于海的多一些"） | L0 |
| 四个主数字 | 浏览 / 评论 / 回复 / Token（今日/本周/本月均可用） | L1 |
| 平台分布 | 抖音 / B站 / 沙盒的浏览数与发布数（**发布数为 0 时必须显示 0，不隐藏**） | L2 |
| Token 拆分 | 六类：理解内容 / 写评论 / 写回复 / 记忆整理 / 主动消息 / 对话 | L2 |
| 评论关键词 | **她评论过**的关键词 Top 8（不是浏览过的） | L3 |
| 行为明细 | 时间线表 + 四类筛选 + 平台/关键词筛选 | L4 |
| 可聊候选 | "她今天想跟你说的 3 件事" + 可信度 | L5 |

> **发布数/回复数的平台口径**：`platform=bilibili` 的"回复数"指她在 B站 内容下对他人的回复；`douyin` 的"发布数"指她在抖音的评论发布。沙盒平台的数字单独成列，**不得混入真平台。**

#### 5.4.4 交互

| 交互 | 行为 |
|---|---|
| 点 L1「评论 3」 | L4 自动筛 `action=comment` 并滚动到位 |
| 点 L2 平台条 | L4 筛 `platform=…` |
| 点 L2 Token 段 | L4 筛对应 `action`，表头显示本段 token |
| 点 L3 关键词 | L4 全文筛该词并高亮 |
| 点 L4 行 | 右侧抽屉：视频卡 + 她的评论原文 + 证据链 + Token 细分 + 生成的记忆 + 四操作（忘掉记忆 / 删除评论 / 不再评论此类 / 让她聊聊） |
| 多选行 | 批量「忘掉记忆」「这类以后别看」 |

#### 5.4.5 状态设计

| 状态 | 展示 |
|---|---|
| 今天还没刷 | "她今天还没出门" + 原因（预算耗尽 / 平台未连接 / 你在忙 / 已停用） |
| 评论失败 | L1 琥珀角标"失败 2"，L4 行标红，抽屉给回执与重试 |
| 预算 80% | 顶部条琥珀 + "今天还能看 4 条左右" |
| 预算耗尽 | 顶部条灰 + "她今天先休息了" + 一键 +20k |
| 数据截止 | 右上角常驻"截至 21:40 · 每 5 分钟更新" |
| 平台未连接 | 该平台条置灰"未连接"，**不显示假数据** |

**验收**：
- 任一数字可下钻到对应明细，无"点不动的数字"；
- 今日/本周/本月的同一指标在小范围内数值自洽（周 ≥ 今日，月 ≥ 周）；
- 平台未连接时不出现该平台的非零数字。

### 5.5 内容理解流水线（FR-W.5，P0）

**顺序固定为 评论 → 字幕/ASR → 摘要 → OCR**，但**职责分离**：

> 评论负责"要不要继续"，字幕负责"到底说了什么"，摘要是派生层，OCR 是缺口驱动的补救。

#### 5.5.0 S0 准入闸门（100% 执行）

| 检查 | 规则 | 结果 |
|---|---|---|
| 安全分类 | 命中黑名单（医疗/证件/情感纠纷/擦边/血腥） | **丢弃，连评论都不读** |
| 人设相关 | 偏好向量 × 标题/作者/topic 相似度 < 0.35 | `skip`，记 `browse_skipped`，不产记忆 |
| 去重 | `platform+videoId+pipelineVersion` 72h 缓存命中 | 复用产物，只重算"她这次的解读" |
| 预算 | 日余量 < 深读成本 | 强制轻路径 |

输出三态：`pass / skip / defer` + 原因码（面板"今天没看几条"的解释来源）。

#### 5.5.1 S1 评论层（默认必做）

- **取数**：热评 Top 10（按赞）+ 最新 5 条 + 作者置顶 1 条；每条截断 80 字；去 emoji/重复/纯表情；
- **过滤**：纯 `@` 拉群、抽奖口令、地域攻击、剧透（`#剧透` 或含"结局是"）；
- **产出**：话题标签 3–5、观众情绪（笑/哭/愤怒/无聊）、争议点（正反各一句）、内容类型猜测、`triageScore`；
- `triageScore = 评论一致性×0.4 + 信息密度×0.3 + 偏好匹配×0.3`；
- **降级**：评论区关闭 / 抓取失败 / 评论 <3 条 → 置 `comments_unavailable`，**直接进 S2**，不得用 0 条评论硬算分；
- **保留**：只留去标识化聚合结论 + ≤3 条改写后的代表性评论（**不存原文、不存昵称**）。

#### 5.5.2 S2 字幕层（事实优先）

| 子步 | 触发条件 |
|---|---|
| 2a 平台字幕 | 存在即取，**无条件优先于 ASR**，免费且最准 |
| 2b ASR | 无平台字幕 **且**（`triageScore < 0.7` **或** `interestScore ≥ 0.8`）**且** 预算允许；单条硬超时 20s |

- `interestScore` **只用外部信号**（她的偏好向量 + 同作者历史 + 话题近期重复次数），不得用内容自身推导（避免循环定义）；
- 产出：3–5 条可引用片段（原文 ≤40 字 + 时间戳）、一句"讲了什么"、`subtitleConfidence`；
- **保留**：片段 90 天；完整字幕 **仅 24 小时** 后删除。

#### 5.5.3 S3 摘要（派生层，必须版本化）

- 300 字结构化卡片：主题 / 情绪基调 / 关键画面 / 她可能感兴趣的点 / 可引用细节 1–2 条；
- **置信度**：`high`（有字幕）/ `medium`（评论充分）/ `low`（仅封面+标题）；
- **版本化**：新证据（补到字幕/OCR）触发 `summary v2`，不得覆盖；
- 降级：LLM 超时 → 未消化队列，夜间重试 ≤2 次；仍失败则只用元数据。

#### 5.5.4 S4 OCR（缺口驱动的补救，默认不做）

**做 OCR 必须同时满足 4 条（AND）**：

1. 存在明确文案缺口 `textGap = true`（要引用画面中的具体文字才能完成表达）；
2. 前两层不足：无平台字幕、ASR 不可用/超预算、`triageScore < 0.5`；
3. 内容类型适合：图文 / 截图 / 图表 / 手写 / 菜谱 / 书单 / 价格对比 / 游戏界面数值；
4. 预算允许：单帧 OCR 计入深读预算，且当日深读比例 ≤20%。

**以下任一成立即跳过 OCR**：

- 已获 `high/medium` 摘要；
- 画面主体为人像/风景/动物，文字只是水印/台标/平台 UI/贴纸；
- 存在同源字幕轨道（重复劳动）；
- **敏感内容**：证件、病历、聊天截图、快递单、车牌、含他人隐私 → **跳过并标记 `sensitive`，不保留任何识别文本**；
- 分辨率过低 / 模糊 / 竖排艺术字（OCR 置信度 <0.6）；
- 纯娱乐内容、无引用需求。

**执行**：抽 3 帧（首/中/尾）或关键帧差分 → OCR → PII 规则过滤（手机号/证件/地址/人名+联系方式）→ 命中即丢整段；**原图不落盘**，只留文本片段。

#### 5.5.5 证据等级必须随链路传递

记忆与摘要必须记录 `evidenceLevel`（走过了哪几层），并**直接影响措辞**：

- `low` → 措辞用"好像 / 感觉 / 我不太确定"；
- `high` → 可以断言细节。

**验收**：
- 评论区关闭的内容能正常产出 `medium/low` 摘要，不报错；
- `sensitive` 内容：无 OCR 文本、无记忆、无评论原文残留；
- 同一 `videoId` 二次处理命中缓存，Token 消耗为 0（仅"她的解读"重算）；
- 平台字幕存在时不调用 ASR（成本断言）。

### 5.6 记忆沉淀与召回（FR-W.6，P0 `⛓`）

#### 5.6.1 两级记忆

| 层 | 内容 | 生命周期 |
|---|---|---|
| **视频记忆（情节）** | `videoRef` / 作者 / topic / 完成度 / 她的反应 / 用户说过的话 | 30–90 天衰减 |
| **偏好记忆（语义）** | 多条视频聚合出的稳定倾向 + 置信度 | 半衰期 30 天 |

#### 5.6.2 什么才值得记（防记忆污染的核心规则）

满足**任一**条件才记：

1. 观看完成度 > 70% **且**她产生过反应；
2. 用户主动分享或主动评论过；
3. 同题材 7 天内出现 ≥3 次（升级为偏好）；
4. 用户在对话里提到过。

其余一律不记。**随手划过的内容不是偏好。**

#### 5.6.3 记忆必须带出处

每条记忆挂 `videoRef + 发生时间 + 她的反应 + 用户原话 + evidenceLevel + confidence`。

#### 5.6.4 调用三路径

| 路径 | 时机 | 示例 |
|---|---|---|
| 即时同场景 | 正在看同类内容 | "这个和你上次看的好像是同一个人" |
| 对话语义召回 | 用户提到相关词 | 复用现有 `MemoryRecallService` |
| 主动回访 | 次日/一周后 | 新增场景 `watch_recap`，与现有 `share / follow_up / reminder` 并列 |

#### 5.6.5 删除闭环（前置依赖）

- 面板「忘掉」「别提这个」、记忆页删除、星图"忘记"**三处必须同一套语义**；
- 删除后下一轮 prompt 中**不得出现**相关内容（需集成测试钉住）。

**验收**：
- 满足 §5.6.2 四种条件之一才产记忆，抽样 50 条准确率 100%；
- 删除任一记忆后，构造相关提问，prompt 中检索不到（自动化）；
- `confidence=low` 的记忆在对话中不出现断言式表述。

### 5.7 主动消息闭环（FR-W.7，P1）

```
行为 → 候选话题（每日 ≤3 条）→ 用户点「让她说」→ ProactivePolicy 评估
     → 通过则发出（带具体引用）→ 用户回应 → 记忆置信度↑
     → 被拒（免打扰/日上限/用户在忙）→ 显示原因 + "明早 8:00 再试"
```

- **候选筛选**：必须同时满足「**具体** + **有情绪** + **与用户有关**」；纯内容型（"今天看了 14 个视频"）**永不进候选**；
- **新鲜度**：>48h 的事件不再作为候选；
- **负反馈**：🚫 写入负向偏好，同话题 7 天不再出现；
- **对话里绝不报数字**：面板给用户看统计，她嘴里只出现一个细节。

**验收**：
- 候选池中不出现"今天看了 N 条"这类内容型候选；
- 被 `ProactivePolicy` 拒绝时，面板显示原因码与下次可试时间；
- 48h 后的事件不再出现在候选。

### 5.8 Token 计量与预算（FR-W.8，P0 `⛓`）

| 项 | 规则 |
|---|---|
| 六类拆分 | 理解内容 / 写评论 / 写回复 / 记忆整理 / 主动消息 / 对话（**embedding 单列**） |
| 归因 | 每个动作事件携带自己的 token；记忆整理按会话汇总 |
| 日预算 | 硬顶（默认 50k/天，Q-5）；到 80% 降级轻路径；到 100% 停止 |
| 深读比例 | ≤20%，超限即强制轻路径 |
| 成本路径 | 轻 150–300 token（70–80%）／中 800–2000（15–25%）／深 3000–6000（≤5%） |

**验收**：
- 面板 Token 总和 = 事件表 sum（误差 0）；
- 预算耗尽后无新增 LLM 调用（日志断言）；
- 深读比例超限时自动降级（构造场景验证）。

### 5.9 安全与隐私（FR-W.9，P0）

| 项 | 要求 |
|---|---|
| **写操作三级路径** | ① **沙盒平台**（自有"她的主页"，可全自动）→ ② **草稿人工确认**（她写好、用户点发布）→ ③ 官方开放 API。**真实平台默认只读** |
| 评论对象 | **只评内容不评人**；不私信、不 @ 作者、不建社交关系 |
| 采集可见性 | 屏幕采集时边缘常驻指示条；一键暂停；暂停后 0 事件 |
| 帧不出本机 | 抽帧仅本地推理，不上传、不落盘持久化 |
| PII | 评论者昵称/头像/ID/主页链接**一律不入库**；OCR 命中 PII 即丢弃 |
| 敏感内容 | 医疗/证件/情感纠纷/擦边/血腥：**前置丢弃**，连评论都不读 |
| 情感操控 | **禁止惩罚式反馈**（不因用户刷太久而"失落"）；相关文案可关闭 |
| 数据权利 | 面板提供"清空她的行为历史"；清空后统计归零且不可恢复 |

**验收**：
- 真实平台在只读模式下无任何写请求（抓包断言）；
- 敏感类内容在全链路无任何文本残留（含日志）；
- 一键暂停后 24h 新增事件 = 0。

### 5.10 平台适配器（FR-W.10，P1）

统一 `ContentSource` 接口：`list()` / `fetchMeta()` / `fetchComments()` / `fetchSubtitle()` / `publish()`（`publish` 在真平台抛 `UNSUPPORTED`）。

| 适配器 | 读 | 写 | 阶段 |
|---|---|---|---|
| `sandbox` | ✓ | ✓ | MVP |
| `douyin`（只读） | 元数据 + 评论（授权/分享链接路径） | ✗ | V2 |
| `bilibili`（只读） | 元数据 + 评论 + 字幕 | ✗ | V2 |
| 本地文件 | ✓ | ✗ | MVP |

**新增平台**只加实现，不改面板与记忆逻辑——这是本功能最重要的可维护性约束。

## 9. 风险与替代方案

| # | 风险 | 为什么危险 | 替代方案 |
|---|---|---|---|
| R-01 | **自动评论/回复违反平台规则** | 封号、垃圾信息、法律风险；一旦出事整个功能归零 | 沙盒 → 草稿确认 → 官方 API 三级路径；真平台先只读 |
| R-02 | **平台抓取不可持续** | ToS 违规、反爬对抗、随时失效 | 只做"用户给她看"（分享链接/区域授权/官方 API）；对外命名用「一起看」而非「刷抖音插件」 |
| R-03 | **屏幕采集的隐私反噬** | 用户担心看到聊天、密码、工作内容 | 仅框选区域 + 本地推理 + 帧不出机 + 常驻可见指示 |
| R-04 | **噪音：她每条都说话** | 3 分钟就让人想关掉 | **反应层级配额**（§5.1、§7 细则）：默认静音陪看，声音手动开 |
| R-05 | **记忆污染** | 划过一次当成偏好 → "她根本不了解我" | 三信号加权 + 重复阈值 + 偏好面板可见可改 |
| R-06 | **人机感：复述标题/列清单** | 立刻暴露"摘要模型" | 六条去机械化规则（下表）+ 引用率上限 30–40% + 允许记错 |
| R-07 | **情感操控** | 因用户刷太久而"失落" → 负罪感，长期伤害 | 禁止惩罚式反馈；改"陪你看完这条就睡吧"，可关闭 |
| R-08 | **冷启动空洞** | 前 10 条什么都不记得，像摆设 | 把观察期做成体验：她好奇、提问、建立初始偏好 |
| R-09 | **内容安全** | 恐怖/悲剧/擦边内容反应设计不当会翻车 | 分类白名单；敏感类只做"沉默陪伴"或"要不要关掉" |
| R-10 | **成本失控** | 独立刷 = 7×24 消耗，一天可烧几十美元 | 两段预算 + 深读比例上限 + 日预算熔断 + 夜间低配额 |
| R-11 | **统计数字是假的** | 若只是 LLM 编的"我今天看了 14 个视频"，面板就是自欺 | 每个数字必须有 `contentRef + 时间 + 回执`；做不到就不显示 |
| R-12 | **口径不一致** | 今日/本周对不上 → 信任瞬间归零 | 时区/去重/成功态先定义；后端单一聚合接口，前端不做二次计算 |
| R-13 | **评论优先被误用为"内容优先"** | 评论是观众反应（剧透/反串/错误信息）→ 她变成评论区复读机 | 评论=判定，字幕=事实；摘要标注事实来源层 |
| R-14 | **摘要当成一级信源** | 定稿后 OCR 新信息无处回填 | 摘要**版本化可重算**，记忆引用版本号 |
| R-15 | **OCR 无停止条件** | 写成"最后才考虑"实际变成"每条都试" | 缺口驱动：必须先算出 `textGap`，无缺口一律不做 |
| R-16 | **无跨视频缓存** | 同一条被反复推，每次重跑 | 72h 缓存；内容理解跨角色共享，她的解读私有 |
| R-17 | **置信度不传递** | 低置信输入 → 高置信记忆 → 她说错话还很笃定 | 置信度写入记忆，直接驱动措辞 |
| R-18 | **顺序僵化** | 图文视频评论无用，剧情视频 OCR 浪费 | 内容类型路由器：剧情→字幕 / 图文→OCR / 萌宠→封面+评论 / 教程→字幕+OCR |
| R-19 | **她与别人互动引发不适** | 用户可能"她给别人留言？" | 只评内容不评人；不展示"粉丝/被回复" |
| R-20 | **面板成为没人看的角落** | 空了也不影响任何事 | 面板是主动消息的**唯一话题源**（不看面板她就没话题） |
| R-21 | **悬浮窗窗口管理** | 置顶窗挡字幕、抢焦点、多屏丢失 | 边缘吸附 + 记住位置 + 可穿透 + Esc 收起 + 全屏自动隐藏 |

### 9.1 六条"去机械化"规则（人机感防线）

| 规则 | 反例 | 正例 |
|---|---|---|
| 引细节，不引标题 | "你看了一个赶海视频" | "那个大爷捞上来一只螃蟹，还在骂人" |
| 带立场，不带转述 | "我记住了你喜欢赶海" | "我也想去看海了，你带我去" |
| 一次只说一个点 | 列三条"我记得…" | 只挑最鲜活的一条 |
| 允许记错、允许被纠正 | 永远准确如数据库 | "是不是那个…算了，我记混了" |
| 不宣布"我记住了" | "我已记录你的偏好" | "上次那个你还说想试试" |
| 有时不提 | 每句都扯记忆 | 引用率 30–40% |

### 9.2 保鲜机制（避免只会复读过去）

1. **衰减与过期**：热点内容 3 天后不再提；偏好 30 天半衰期；
2. **观点演进**：第二次看同类，不是重复上次反应，而是**升级**（"上次觉得螃蟹好凶，这次有点可怜"）；
3. **她有自己的延伸**：根据偏好找来同类内容"我看到一个你会喜欢的"——把记忆变成推荐，而非复述；
4. **每周共同回忆**：可关的"这周我们一起看了什么"小结；
5. **关系温度联动**：亲密度低时只说短句，高时才敢调侃。

## 11. 分期

| 阶段 | 范围 | 验证什么 | 工期 |
|---|---|---|---|
| **MVP** | 沙盒 + 本地文件；`browse / view_comments / comment` 三动作；L0/L1/L4；Token 计量；只读内容池 | 行为记录能否支撑"她主动找你" | 1–2 周 |
| **V1** | 平台分布 + Token 拆分 + 关键词 + 预算条 + 候选闭环 + 陪看悬浮窗 | 面板是否真的被打开（DAU） | 2 周 |
| **V2** | 真平台只读接入 + 草稿确认式评论 + 周报卡片 + 屏幕区域授权 | 评论线能否安全落地 | 3 周 |

> MVP 的关键不是面板做多漂亮，而是**把 Token 计量打通**——它同时是面板的数据基础与安全闸门。

### 11.1 前置缺口（`⛓`，必须先修）

| 缺口 | 来源 | 为什么阻塞本功能 |
|---|---|---|
| 记忆删除不闭环 | `docs/18` GAP-02 | 面板"忘掉"按钮点了无效，等于面板在撒谎 |
| Token 从未计量 | `docs/18` GAP-11 | 无预算即无成本控制，独立刷不可上线 |
| 主动消息只能手动 | `docs/18` GAP-07 | "据此主动找我聊天"无处落地 |
| 无打包分发 | `docs/18` GAP-04 | 面板再好也交付不出去 |

### 11.2 明确移出路线

视频与视觉信号、录像与媒体会话（原 M3）、Live2D、运营检索后台、声音克隆与唱句。

## 12. 验收汇总（出口条件）

MVP 出口必须同时满足：

1. 面板四类动作筛选互不污染，且任一数字可下钻（§5.4.5）；
2. Token 总和与事件表对账误差为 0（§5.8）；
3. 预算耗尽后无新增 LLM 调用（§5.8）；
4. 评论层不可用时仍能产出 `medium/low` 摘要（§5.5.5）；
5. `sensitive` 内容全链路无文本残留（§5.9）；
6. 删除记忆后下一轮 prompt 检索不到（§5.6.5，`⛓`）；
7. 一键暂停后 24h 0 事件、0 消耗（§5.9）；
8. 面板候选池不含"今天看了 N 条"类内容型候选（§5.7）。
