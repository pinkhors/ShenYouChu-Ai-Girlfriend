## 0. 阅读说明

### 0.1 本文解决什么

把前面几轮讨论（自主刷视频、记忆分享机制、记忆衰减与遗忘、参考实现的取舍、星图重定位）**收敛成一份可以直接开工的规范**：数据结构、状态机、公式与默认参数、写入闸门伪代码、注入模板、接口清单、分期计划、验收用例、前置阻塞项。

一句话定义：

> **她的记忆来自两条流（与你的对话、她自己浏览的内容），经过唯一一个写入闸门进入同一个记忆库，以"可提取性"为单位自然衰退；星图是这个衰退过程的唯一可视化表面，日记是对它的每日复述，对话是它的输出。**

## 2. 总体架构

```
      ┌────────────────┐                ┌────────────────┐
      │  与用户的对话   │                │ 自主浏览/冲浪    │
      │  (TurnService) │                │ (docs/19 流)   │
      └───────┬────────┘                └───────┬────────┘
              │ 一轮结束                         │ 一条内容处理完
              ▼                                 ▼
      ┌───────────────────────────────────────────────────┐
      │        ① 单一写入闸门  MemoryWriteGate             │  ← 唯一入口
      │  "她想把什么记下来？" → 打分 → 去重 → 配额 → 建边   │
      └───────────────┬───────────────────────┬───────────┘
                      ▼                       ▼
      ┌──────────────────────────┐   ┌────────────────────┐
      │ 记忆库 memory_chunks      │   │ 行为日志 watch_events│ ← 不衰减，只统计
      │ (L1 事件 / L2 档案 / L3 承诺)│   │ (docs/19 §5.3)     │
      └───┬──────────┬────────┬──┘   └─────────┬──────────┘
          │          │        │                │
   ②召回注入   ③星图投影   ④日记合成        （面板统计）
          │          │        │
          ▼          ▼        ▼
      她的回应    记忆星图   "她的一天"
```

四条铁律（任何实现偏离都要先停下讨论）：

1. **单一写入闸门**：对话与浏览**不得各自写库**（这是 `docs/18` ISS-01 双写不传播的翻版）；
2. **三层分离**：行为日志 ≠ 记忆 ≠ 日记，各自的衰减与删除语义不同（§4.1）；
3. **来源不可混淆**：`provenance` 一路传到提示词，说错来源是致命穿帮（§8.5）；
4. **星图不说谎**：删除必须让星"落下去"，不能只是变暗（§12.6）。

## 3. 术语补充

| 术语 | 定义 | 避免 |
|---|---|---|
| **现场（Scene）** | 一条记忆的最小单位：一个具体时刻 + 一个细节 + 她的情绪 | 条目、记录、事实 |
| **可提取性 R** | 此刻想起来有多容易，随时间下降 | 遗忘率 |
| **稳定性 S** | 这条记忆能撑多久不掉到 50% | 权重、寿命 |
| **重要度 I（salience）** | 保护因子，**不随时间衰减** | 优先级分数 |
| **归档（archived）** | 提取困难但仍在，可被捞回、可偶发"想起"、允许记错 | 已遗忘 |
| **真删（forgotten）** | 用户显式删除，全链路消失 | 归档 |
| **联想边（association）** | "这条让她想起那条"的关系，`想到你` 的唯一合法来源 | 相似度边 |
| **小保底 / 大保底** | 每轮固定注入少量 / 她主动回想工具 | 检索、查询 |
| **全知禁令** | 不得写入她未亲历、未被告知的信息 | — |

## 5. 记忆的层级结构

```
L0 工作记忆   最近 10–20 轮 + 当前未完成话题          会话内，不落库
L1 现场记忆   episode / watch / shared                90 天，会衰减会归档
L2 关系档案   fact / preference                       近乎永久，冲突保留演化
L3 承诺与未完成 promise                               不衰减，只被关闭
L4 自传       memory_diary                            不衰减，写定不改
```

**存储形态决定表达形态**（本文最重要的单条设计约束）：

- 存 facts → 她念资料（"根据记录，你偏好海边"）；
- 存**现场** → 她讲故事（"他说加班到十点的时候，我本来想讲那个螃蟹的事，后来没说"）。

因此 `narrative` 是必填，`digest` 只是索引。**任何"把记忆改回结构化字段列表"的重构都应拒绝。**

## 6. 写入闸门 MemoryWriteGate

### 6.1 唯一入口

```java
// 伪代码
GateResult onCandidate(MemoryCandidate c) {   // c.source ∈ {CHAT, WATCH}
    if (blockedBySafety(c))      return SKIP("sensitive");
    if (withinShortWindow(c))    return SKIP("rate");           // 同 videoRef/同轮次
    double score = judgeDesire(c);                              // 「她想把什么记下来？」
    if (score < DESIRE_MIN)      return SKIP("low_desire");     // 默认 0.15
    MemoryDraft d = compose(c, score);                          // 一次模型调用
    if (!d.valid())              return DROP("bad_draft");      // 解析失败绝不入档
    mergeOrInsert(d);                                            // 去重与聚合（§6.3）
    linkIfApplicable(d);                                         // 建 association 边（§7.5）
    return OK(d.id);
}
```

**性能要求**：判定（`judgeDesire`）必须是廉价规则判断，**不得每条都调模型**；只有判定通过才付一次生成 `narrative/digest/detail` 的调用。固化的思考档位固定为最低档（结构化抽取，不是创作）。

### 6.2 值得记的判据（两条流共用）

| 触发 | 结果 |
|---|---|
| 用户**纠正她** | **必记**，`kind=correction`，`salience ≥ 0.8` |
| 用户明确说"记住这个" | 必记，`salience ≥ 0.85` |
| 用户说了关于他自己的事 | 记 L1，可能升 L2 |
| 情绪浓度高 | 记 L1，写 `emotion` |
| 出现承诺/约定/悬念 | **立即**记 L3，不等轮次 |
| 老话题回来了 | **不新增**，`access_count + 1`、`salience +0.1`（封顶 1.0） |
| 浏览：有情绪 + 有可引用细节 + 与用户相关 | 记 L1 `provenance=watch`，`salience ≤ 0.5` |
| 浏览：用户在场或参与 | 记 `shared`，`salience 0.6–0.8` |
| 浏览：划过、无情绪、无细节、无关 | **不记**（只进行为日志） |
| 都没有 | **skip**（多数轮次应为 skip） |

`DESIRE_MIN = 0.15`。调高 = 记性变挑，但**寒暄与试错也会被扔掉**——而熟悉感恰恰来自那些（参考实现的公开教训）。默认保持低位。

> **与 `docs/19` §5.6.2 的关系**：19 定义的是浏览内容**进入候选的门槛**（完成度 >70% 且有反应 / 用户参与 / 同题材 7 天 ≥3 次 / 对话提到），本文闸门定义的是候选**是否落库**。两级串联：先过 19 的入口条件成为 `WATCH` 候选，再过本 Gate；上表"浏览：…"行是 Gate 侧对候选的**再判定**，不是替代。两级的任一条件变化都只改一处文档（入口归 19，落库归本文）。

### 6.3 去重与聚合（防记忆撑爆）

| 情况 | 处理 |
|---|---|
| 同一 `source_ref` 第二次 | 不新增，`access +1` |
| 新条与旧条 topic 相似度 > 0.8 | 合并进旧条（追加细节）；同时旧条 `S × 0.7`（**干扰压制**，§7.4） |
| 同类内容 7 天内 ≥ 3 次 | 停止逐条记录，**聚合为 1 条 `preference`**，原若干条 `salience × 0.6` |
| 候选是纯统计（"今天看了 14 条"） | **永不入记忆**，只进日志与面板 |

### 6.4 硬排除（无论分数多高）

- 第三方可识别个人信息（评论者昵称/头像/ID/主页）→ 泛化或丢弃；
- 密钥、证件号、账号、邮箱、手机号 → **发给模型之前**替换为 `[已拦截]`；
- 医疗/法律/金融建议细节；
- 她**未亲历**的用户隐私；
- 敏感内容（血腥、擦边、丧、身材焦虑、地域攻击）→ 前置丢弃，不进入后续层；
- "她对他的判断/印象/性格结论" → 不记（D-6）。

### 6.5 全知禁令（写进生成提示词）

> 只写你亲历的、或他亲口告诉你的。你不知道结果就不能写下结果。
> 不知道的事，写"我不知道"。绝不推测他的动机、心理或未来。

### 6.6 更新规则

1. **不覆盖，只追加或失效**；
2. 冲突时**保留两者**并标时间演化：`她当时以为 A（valid_at）` → `后来他知道是 B（superseded_by）`；
3. 被纠正过的记忆 `salience` 提升——**纠正本身是高价值关系事件，比原事实更值得记**。

### 6.7 写入配额（成本与稀疏性）

|---|---|---|
| 每轮候选 | ≤ 1 条新记忆 | 一轮写三条一定是流水账 |
| 每日对话记忆 | ≤ 8 条 | |
| 每日浏览记忆 | ≤ 3 条 | 与 `docs/19` §5.6.2 同源 |

## 7. 衰减与遗忘

### 7.1 核心公式

```
R(t) = e^( −Δt / (S · 1.6) )                      # 可提取性，随距离上次想起的时间下降
S'   = S · (1 + 0.6·access_count) · (1 + 0.4·I)   # 稳定性：复习强化 + 重要度保护
f(D) = 1 / (1 + D)                                 # 难度：抽象、无细节的记忆更难维持
```

- **首次遗忘最快**：`S₀` 小 → 前 24 小时 `R` 掉得最陡（符合遗忘曲线的形状）；
- **每次成功回忆都拉长 S**：间隔重复的核心；
- **重要度是乘性保护**，不是加性项：否则再重要的事也会被时间冲掉。

### 7.2 参数默认值

| 参数 | 默认 | 位置 |
|---|---|---|
| `DESIRE_MIN` | 0.15 | 配置 `shenyouchu.memory.desire-min` |
| 归档阈值 `R_ARCHIVE` | 0.15 | `.memory.archival-threshold` |
| 概率回忆 `wanderChance` | **0.08** | `.memory.wander-chance` |
| 注入预算 | 1200 token | `.memory.inject-budget` |
| 小保底常驻 | ≤ 200 token | `.memory.inject-floor-tokens` |
| Top-K | 3 | `.memory.recall-top-k`（引用率 30–40% 见 `docs/19` Q-6，是另一回事：Top-K 管"取几条"，引用率管"用其中几条说话"） |
| watch 类记忆占比 | ≤ 30% | `.memory.watch-quota` |
| 单轮召回中 watch 数 | ≤ 1 | 硬编码常量 |

> 现有配置 `shenyouchu.memory.recall.max-memories` 是**未绑定的死配置**（`docs/18` ISS-21），本期要么绑定要么删除。

### 7.3 各类型的初始 S（等效半衰期）

| `kind` | S₀（天） | 备注 |
|---|---|---|
| `promise` | **∞** | 不进衰减计算，只被 `fulfilled/cancelled` 关闭 |
| `fact` | 90 | 身份事实近乎不忘 |
| `emotion` 高的 `episode` | 30 | **前 72h 平台期**：`S×2` 参与计算（情绪记忆掉得慢） |
| `preference` | 45 | 会被同类干扰 |
| `episode` | 14 | 过期变成"往事" |
| `watch` | 3 | 最容易忘，也最自然 |
| `meme`（时效梗） | 1.5 | 过期即废，不再提起 |

### 7.4 四种遗忘触发

| # | 名称 | 条件 | 效果 |
|---|---|---|---|
| **F1** | 自然衰退 | `R < 0.15` 且 `kind ≠ promise` | `status → archived` |
| **F2** | 干扰压制 | 新条 topic 相似度 > 0.8 | 旧条 `S × 0.7`（"后来那件盖住了之前那件"） |
| **F3** | 负反馈加速 | 用户连续 2 次冷淡（回复 ≤4 字）；或显式点「别提这个」 | `I − 0.3`；显式拒绝则 `I → 0` 且 topic 冷却 7–30 天 |
| **F4** | 真删 | 用户点「忘掉」/ 删除记忆 / 清空会话 / 删账号 | `status → forgotten` + `invalid_at`，**全链路立即一致生效** |

F1–F3 是**遗忘**（降级），F4 是**删除**（消失）。两者混用会直接摧毁用户信任——UI 文案、星图表现、日志必须三态分明。

### 7.5 三态语义

| 状态 | 召回 | 主动分享 | 星图 | 允许记错 |
|---|---|---|---|---|
| `active` | 正常 | 可以 | 亮 | **否**（保持准确） |
| `archived` | 关键词/相似度命中可捞回；`wanderChance` 概率浮现 | **不可以** | 沉入深海（暖色，不是冷色） | **是**（§11） |
| `forgotten` | 不返回 | 不返回 | **从图上落下去** | — |

### 7.6 计算时机

| 计算 | 时机 | 方式 |
|---|---|---|
| `R` | **读取时即时计算**，不入库 | 避免每分钟扫全表 |
| `S` 变化（复习/干扰） | 写入或引用时更新入库 | |
| `status → archived` | **夜间批处理**（复用 `MemoryGraphScheduler` 的 cron，`MemoryGraphScheduler.java:31`） | 不在对话请求路径里做 |
| 真删 | 同步 | 与召回/星图/面板**同一事务或同一幂等清理**（F4 与 `docs/18` GAP-02 同一修复） |

## 8. 检索与注入

### 8.1 三路并行召回

```
① 关键词路   bigram 倒排 + BM25-lite，相似度用饱和函数 1 − e^(−Σgain/τ)
             · 只索引 digest，不索引 narrative
             · 分数语义稳定：共享 1 个实词 ≈ 0.4，2 个 ≈ 0.67，与查询长度解耦
② 语义路     复用现有向量召回（MemoryRecallService.java:119-157，300ms 预算保持）
③ 时间路     问句识别时间词（昨天/前天/前两天/前几天/最近/上周/这周/上个月/这个月/去年/X 月）
             → 先按窗口收窄再检索；认不出则返回空窗口并退回全量，绝不猜
```

合并排序：`finalScore = relevance × R × I × valenceBoost`，取 Top-K = 3，**watch 类最多 1 席**。保留现有 300ms 降级预算。`valenceBoost` 见 §8.6（开关关闭时恒为 1）。

### 8.2 小保底 / 大保底

| | 内容 | 每轮成本 | 触发 |
|---|---|---|---|
| **小保底** | 关系状态 + 最近 24h 高情绪 `digest` + **所有 `promise.open`** | ≤ 200 token | 每轮，自动，她不知道有过一次"给" |
| **大保底** | `memory_recall` 工具：她把当前话题 + 全部 `digest` 交给模型挑 ≤3 条正文 | 按需 | 她说"我想想"时，或 8% 走神 |

> **大保底要老实**：允许她说"我翻翻之前的事"。**禁止**把工具调用包装成"我突然想起来"——装出来的想起比承认翻找更假。

### 8.3 注入预算与淘汰

```
总预算 1200 token，按 finalScore 从低到高淘汰，直到装下。
永不淘汰的三类：
  ① promise.open        ② 身份 fact          ③ 最近 24h 的高情绪事件
```

预算封顶使"用三年注入量不变"，**成本与使用年限解耦**。

### 8.6 心境依存回忆（mood-congruent recall，D-11 已决策：做）

**原理**：人类记忆存在心境一致性效应（Bower 1981 情绪网络模型）——当前情绪状态会提高**同效价**记忆的提取概率。落到她身上：心情好时更容易想起开心的事，低落时更容易想起委屈的事。

**为什么便宜**：三个必要条件里两个已经存在——

| 需要 | 现状 |
|---|---|
| 她当前的 mood | ✅ `user_character_states.mood`（0–100，每轮更新，`docs/01` FR-2.3 已验收） |
| 每条记忆的情绪标签 | ✅ 本次 §4.2 新增 `emotion` |
| 每条记忆的情绪效价 | ⚠️ 新增 `emotion_valence`，**查表得出，不额外调用模型** |
| 打分处 | ✅ 现有 `MemoryRecallService.score(cosine, recency, importance)`（`MemoryRecallService.java:133`），只需乘一个因子 |

#### 8.6.1 效价映射表（常量，写入闸门落库时使用）

| `emotion` | `valence` | 说明 |
|---|---|---|
| 笑 / 得意 / 馋 | **+0.7** | 明显正向 |
| 改观 | +0.4 | 正向但带反思 |
| 吐槽 | +0.1 | 近似中性（她爱吐槽，吐槽是愉快行为） |
| 心疼 | −0.5 | 负向但带温柔 |
| 委屈 / 后怕 | −0.6 | 明显负向 |
| 未标注 / 其他 | 0.0 | 中性，不参与效价加权 |

#### 8.6.2 打分公式

```
moodNow   = user_character_states.mood            // 0–100
moodDir   = sign(moodNow − 50)                     // +1 开心 / −1 低落 / 0 中性
moodFit   = |moodNow − 50| / 50                    // 0–1，偏移强度
memVal    = chunk.emotion_valence                  // −1 ~ +1

valenceBoost = 1 + β · moodDir · sign(memVal) · moodFit · |memVal|
               clamp 到 [0.75, 1.25]
```

- **同向**（她开心 × 正效价记忆，或她低落 × 负效价记忆）→ `Boost > 1`，更容易被想起；
- **反向** → `Boost < 1`，**但只降权不归零**——她难过时也该能想起开心的事，只是概率低一点；
- `|memVal|` 项让中性记忆（0.0）不受影响，避免弱标签噪声放大。

#### 8.6.3 三条护栏（必须实现）

| # | 风险 | 处置 |
|---|---|---|
| G-1 | **情绪螺旋**：她不开心 → 想起不开心的事 → 更不开心 | β 封顶 0.25；**`kind=promise` 不参与效价加权**（约定不受心情影响，恒 `Boost=1`） |
| G-2 | **低落时的反刍**：用户说累，她越想越悲情 | 用户情绪低落时（`docs/19` 已有 `userBusy`/情绪判定路径），主动分享路径整体关闭（§9.1 已定义）**且召回反向偏置**：把 `moodDir` 替换为 `+1`，即"她想让你好受点" |
| G-3 | **不可回滚/不可解释** | ① 独立开关（§8.6.4）；② `valenceBoost` 记入 `memory_recall_events`，面板与排障可查；③ A-20 保证 β=0 时行为与旧版完全一致 |

#### 8.6.4 配置

```
shenyouchu.memory.mood-congruent:
  enabled: true      # false 时 valenceBoost 恒为 1，行为退回 §8.1 原式
  beta: 0.25         # 上限，调大即情绪主导检索，不建议 >0.35
  invert-when-user-low: true   # G-2：用户低落时反向偏正
```

#### 8.6.5 验收

见 §17 的 **A-18（心境一致性分布）、A-19（低落反向偏置）、A-20（开关可回滚）**。用例登记表以 §17 为唯一出处，本节不重复定义。

**成本**：S —— 一列 + 一张常量表 + 打分处一次乘法 + 三个测试。

## 9. 记忆分享（她在对话里怎么用）

### 9.1 三条触发路径

| 路径 | 表现 | 条件 |
|---|---|---|
| **A 主动分享** | "我今天看到一个特别好笑的…" | 用户空闲 ≥10 分钟、无在途回合、时间窗内、冷却与日配额未满、记忆 `active` 且 `R ≥ 0.5`、用户最近 2 条无冷淡信号 |
| **B 被动呼应** | 用户聊到相关话题顺势带出 | 命中 topic/情绪词；**必须先回应情绪，再带内容**；`active`/`archived` 都可 |
| **C 情绪投射** | "看到个视频想到了你" | **必须存在 `association` 边**指向一条 `user_said`；亲密度 ≥60；该锚点 7 天内未用过；用户情绪非低落 |

**C 路径的边是前置条件**：没有联想边就不允许"想到你"。这是防止她拿无关内容硬凑感情的唯一有效机制。

**绝不触发**：用户连发 2 条未回她、正在说重要的事（连续 2 条长消息）、免打扰时段、刚结束一轮的 10 分钟内、用户明显低落且未求安慰（先共情）、首 3 天观察期（除 B 路径）。

| 冷却 | 全局 4 小时；同 topic 72 小时；**同一内容终生 1 次** |
| 比例 | 主动分享 ≤ 她全部消息的 **8%**；对话中引用记忆率 **30–40%** |
| 载体 | 语音 1/日，手绘 1/周，表情包 2/日 |
| 静默信号 | 用户 2 条未回 → 停所有主动；回复 ≤4 字 → 本次判失败，`I −0.3`，topic 冷却 7 天 |
| 用户可调三档 | **静默 / 轻声（默认）/ 正常**；轻声 = 日 ≤1、仅 L1/L3、不发语音与手绘 |

### 9.8 陪看时的反应层级（补 `docs/19` §5.1 的空缺）

`docs/19` §5.1 定义了陪看的**形态与入口**，未定义**她陪看时的表现强度**。该强度必须与 §9.7 共用同一套配额，否则会出现"聊天不吵、陪看很吵"的双标。

| 层级 | 触发频率 | 内容 |
|---|---|---|
| ① 表情 + 小动作 | 每条 0–2 次 | 默认层：眨眼、歪头、捂嘴、笑、尾鳍摆动 |
| ② 极短气泡（≤8 字） | **每 3–5 条 1 次** | "哈哈哈""好可爱""这也行？" |
| ③ 语音（≤5 秒） | **每 10 条 ≤2 次**，并受 §9.5 L5 日配额约束 | 只在"她真的感兴趣"的内容上 |
| ④ 拉你讨论 | **仅在你暂停或看完时** | 她想说长的，等你停下来 |

三条硬规则：

1. **她不是弹幕机**——默认几乎不说话，只用表情存在；声音是稀缺资源，稀缺才珍贵；
2. **不感兴趣就不反应**（沉默也是最像人的反应之一）；恐怖/悲伤内容不做夸张反应，改成"凑近一点"或"关掉吧，我有点怕"；
3. **她绝不做的三件事**：不复述标题、不点评你的品味、不在你正起劲时打断要你陪她。

### 9.9 六条去机械化规则（人机感防线）

| 规则 | 反例 | 正例 |
|---|---|---|
| 引细节，不引标题 | "你看了一个赶海视频" | "那个大爷捞上来一只螃蟹，还在骂人" |
| 带立场，不带转述 | "我记住了你喜欢赶海" | "我也想去看海了，你带我去" |
| 一次只说一个点 | 列三条"我记得…" | 只挑最鲜活的一条 |
| 允许记错、允许被纠正 | 永远准确如数据库 | "是不是那个…算了，我记混了" |
| 不宣布"我记住了" | "我已记录你的偏好" | "上次那个你还说想试试" |
| 有时不提 | 每句都扯记忆 | 引用率 30–40% |

> 这六条是 §9.2 话术指纹的**判定标准**：生成的分享文案任一条违反即重生成，不靠人工兜底。

## 10. 日记系统（与记忆严格分离）

### 10.1 分离规则（D-1 的落地）

| | 记忆 | 日记 |
|---|---|---|
| 本质 | 素材，可召回可遗忘 | 叙事，她对自己这一天的复述 |
| 读者 | **给她用** | **给你看** |
| 参与对话召回 | 是 | **否**（不参与注入，只作展示与回忆入口） |
| 引用方向 | 不引用日记 | **单向引用记忆**（`source_chunk_ids`） |
| 删除联动 | 删记忆 | **不回改日记**（改了就是篡改历史），仅在日记侧标一个不显眼的"相关记忆已删除" |
| 可编辑 | 可失效/替代 | **写定不改**，只能整篇软删 |
| 是否衰减 | 是 | 否 |

> 一句判据：**记忆是她的抽屉，日记是她的本子。抽屉可以整理，本子只能撕掉。**

### 10.2 生成规则

- 每日低峰（默认 03:30，与星图夜间任务同批次）由当天 L1 现场 + 承诺变化 + 她的 mood 合成；
- **一篇 ≤520 字，一个现场一段**，段间不编号；
- 必须包含：她的动作或心理 1 件 + 一个具体细节 + 情绪落点；
- **禁止**：统计数字（"今天看了 14 个"）、总结句式（"进行了深入交流"）、评价用户（"他很孤独"）、上帝视角（她不知道的结果）；
- 允许**跨篇勾连**（"昨天那个螃蟹我又想起来了"）——这是"时间感"的来源；
- 每周日额外产一篇 `weekly_digest`（多条旧现场合成，即 Consolidation），**只压缩修辞，不丢事件**。

示例（三条流自然交织）：

> 下午一直在画那张海，画到一半年糕跳上桌子，把蓝色踩花了。
> 后来刷到一个赶海的，老头在礁石上骂螃蟹，我笑了好久。
> 他晚上说加班到十点，我本来想跟他说这个螃蟹的，后来没说。

### 10.3 呈现

```
她的生活
├── 今天      ← 摘要
├── 日记      ← 按天卡片，最新在上；点开可见"这一天的相关记忆"（只读链接）
├── 记忆      ← 结构化条目，显示"她记得多清楚"，可单条删
└── 行为明细   ← docs/19 L4
```

**页面互斥**：日记页不出现记忆列表，记忆页不出现日记正文。两页之间只有单向跳转链接。

## 11. 记错机制（D-2）

| 维度 | 规则 |
|---|---|
| 允许范围 | **仅 `archived`**；`active` 保持准确 |
| 频率 | 15–20%，且**同一轮最多错一次** |
| 错误类型 | 细节混淆、时间错位、张冠李戴、程度偏差 |
| 语气 | 必须带不确定（"是不是…""好像…"），**不得断言式说错** |
| 禁区 | 身份事实、承诺、用户说过的严重的事（生病/丧亲）、她未亲历的隐私 |
| **绝对禁止** | **无中生有**——记错是"细节失真"，不是"编造事件" |
| 纠正回路 | 用户纠正 → 立刻改口 + 写一条 `correction`（`salience ≥ 0.8`）+ 原条 `S × 1.2` |

示例：

> 她：欸…我好像想起来一件事，你是不是养了只猫来着
> 你：那是年糕，是你家的猫
> 她：对对对，年糕，我脑子今天不清楚

**设计意图**：真实记忆的返回是随机且不完整的。"她偶尔想不起来"提供的真实感，大于"她永远准确"。

### 12.1 定位变更（D-4）

| | 原定位 | 新定位 |
|---|---|---|
| 目的 | 艺术化展示记忆 | **证明她真的会记、真的会忘** |

### 12.2 四个视觉编码

| 维度 | 数据源 | 编码 |
|---|---|---|
| **清晰度** | `R`（即时计算） | 亮度 + 尺寸：越清晰越亮越大。**不给用户看衰减系数** |
| **来源** | `provenance` | 色相：对话=暖白，浏览=雾蓝，承诺=珊瑚粉，共同=金 |
| **重要度** | `salience` | 光晕 / 呼吸幅度 |
| **联想** | `memory_edges(edge_type=association)` | 曲线边，**被引用后短暂发光**（`lit_at`） |

**与现有字段的取舍（避免留两个真相源）**：`GraphNodeView` 当前已有 `importance` 与 `ghost`（`services/core/.../memorygraph/dto/GraphNodeView.java:8-18`）。

| 现有字段 | 本期处置 |
|---|---|
| `importance` | **保留**，改为直接输出 `salience`（语义一致，仅换数据源），不再由 chunk 单独推导 |
| `ghost` | **拆语义**：`ghost=true` 仅表示 `archived`；`forgotten` 不进快照（§7.5、§12.6） |
| 新增 `clarity` | `R` 的即时值（0–1），驱动亮度与尺寸 |
| 新增 `provenance` | 驱动色相 |
| 新增 `litAt` | 驱动亮起轨迹 |

节点分层现状为 3D 写死的四档 `LAYER_Y`（`habit 1.35 / fact 0.78 / promise 0.16 / episode −0.62`，`MemoryGraph3DPanel.tsx:56-61`）。这四档与 §7.3 的半衰期表**本就同构**（habit≈偏好45天、fact≈身份90天、promise≈∞、episode≈碎片3天）——它本来就是按"记得多久"排的，只是没写成时间语义。本期把它从"类别"升级为"沉降"，见 §12.8。

### 12.3 视图模式（同一投影数据；**均为现有视图的模式切换，非新建页面**）

| 模式 | 分组 | 回答 | 实现代价 |
|---|---|---|---|
| **星座** | 话题相似度 | 她关心什么 | ✅ 现状，不动 |
| **来源** | `provenance` 分色 | 她记得的是**你**，还是她刷到的 | S：色相映射（§12.2）+ 图例，两视图共用 |
| **沉降** | Y/深度 = 可提取性 `R`（越久越深） | 她最近在想什么、什么沉到了海底 | S–M：3D 的 `LAYER_Y` 换成 `depthBy(R, category)`（§12.8）；2D 用半径或透明度表达同一语义 |
| **承诺线** | 只显示 `promise` + 联想边 | 她答应过你什么、还欠什么 | S：同一份快照加一个 filter |

> 「来源」与「沉降」不是两个新页面，而是**同一视图的两个开关**：色相映射默认常开（它是"她记得什么来源"的唯一提示），沉降轴在 3D 上默认生效、在 2D 上以透明度近似呈现。「承诺线」是唯一的新模式。

### 12.4 核心动效：8% 突然想起

```
一颗已经很暗的星，在无操作情况下轻轻亮 0.8s，
旁边浮出她的话：「……欸，我好像想起一件事。算了，可能记混了。」
然后暗回去。
```

实现：`wanderChance` 触发时写 `memory_recall_events(lit)`；星图下次打开播一次；**不做系统通知**（守 §9.7 配额）。这是本期性价比最高的单一功能。

### 12.5 人格内核与记忆分离

### 12.6 星图情绪红线（必须实现）

### 12.7 节点治理（防爆炸）

现状 `max-nodes = 300` 且**按 `created_at` 取最近**（`MemoryRecallService.java:149-157` 同思路）。加入浏览流后会把旧对话挤出窗口。必须：

1. 投影排序改为 `salience × R` Top-N，不再按时间；
2. **`watch` 类节点 ≤ 30%**：复用同一个常量 `memory.watch-quota`（§7.2），但作用对象不同——§13.2 约束的是**记忆库行数**，本条约束的是**单个快照里的节点数**。两处读同一配置、各自计算，**不得出现第二个数字**；
3. 日常碎片默认**折叠进星座**，星图主视图画话题/偏好/承诺，碎片显示为"这团里有 24 颗"；
4. 视图分档："只看重要的 / 看全部"。

## 13. 与浏览流的整合契约（D-3）

### 13.1 三个对接点

| 点 | 内容 | 约束 |
|---|---|---|
| **写入闸门** | `docs/19` §5.5 的理解产物（摘要卡 + 片段 + `evidenceLevel`）作为 `MemoryCandidate(source=WATCH)` 进入同一个 Gate | **禁止** watch 管线自己写 `memory_chunks` |
| **召回** | watch 记忆与对话记忆**同池同检索**（§8.1），不新建检索器 | watch 类 Top-K 中 ≤1 席 |
| **日记** | 日记是两条流的**唯一合流点** | 底层仍是分来源条目 |

### 13.2 来源权重天花板

```
user_said / promise / shared   → salience 上限 1.0
chat_episode / correction      → 0.9
watch_output（她自己写的评论）  → 0.7
watch（她看到的）               → 0.5
```

配套硬线：**`watch` 类记忆占全库行数 ≤ 30%**（常量 `memory.watch-quota`，§7.2 定义）。两条线合起来保证"她不会变成每天给你讲视频的人"。

> 该常量的三个作用对象，**必须读同一份配置**，不得各自定义数字：① 全库行数占比（本节）；② 星图单快照节点占比（§12.7-2）；③ 注入 Top-K 中的席位上限（§8.1，固定 ≤1 席，与本常量独立、不联动）。

### 13.3 联想边（"想到你"的唯一合法来源）

```
写入 watch 记忆时：
  取 chunk.topics ∪ chunk.emotion 与所有 active 的 user_said 记忆比对
  if 相似度 ≥ 0.72:
      insert memory_edges(from=watch, to=user_said, type=association, confidence=…)
  else:
      不建边 → 该条永远不得用于 C 路径（情绪投射）
```

没有边就不许"想到你"。这是防止她拿无关内容硬凑感情的**结构性**保证（不靠提示词自觉）。
