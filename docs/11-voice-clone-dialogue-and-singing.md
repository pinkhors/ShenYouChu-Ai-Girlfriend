## 0. 结论摘要

**推荐“一个音色身份、多个渲染器”：对话用 TTS 说话，唱歌用 SVC/SVS 唱；两种模式显式切换，不做“让 TTS 变调唱歌”的假方案。**

具体路线：

| 能力 | 推荐渲染器 | 输入 | 输出 | 阶段 |
|---|---|---|---|---|
| 对话 | TTS（Genie/GPT-SoVITS，见 10） | 文本 / 语音消息 | 短语音，低延迟 | V1 已有方案 |
| 唱歌 V1 | **零样本 SVC**（POC 基准：Seed-VC 类；商用引擎待许可证结论） | 用户哼唱/清唱 10–30 秒 + 目标音色参考 | 保留用户音准/节奏、换成角色音色的翻唱 | V1 |
| 唱歌 V1.5 | **带伴奏点歌**：授权曲库 + 导唱/干声 → SVC | 选歌 + 音色 | 有伴奏的成品翻唱 | V1.5 |
| 唱歌 V2 | **SVS 声库**（如 DiffSinger） | 歌词 + 旋律/乐谱 + 音色模型 | 不依赖真人演唱的高质量歌声 | V2 |

一句话解释为什么不是“一个模型全包”：

- 通用 TTS 不是为唱歌设计的，缺少稳定的长音、颤音、换气与旋律控制；把 TTS 输出变调，通常听起来像机器人哼歌，不能作为唱歌方案。
- SVC 保留**源演唱**的音高、节奏、情绪，只换音色，最适合“你哼一句，她唱给你听”。
- SVS 从歌词和乐谱生成歌声，适合“角色唱一首完整的歌”，但需要曲库/乐谱和按音色训练的声库，成本最高。

**关键前提**：唱歌模式的引擎许可证、曲库版权、GPU 成本和“5–10 秒说话样本不足以覆盖唱歌音域”这四件事，必须先过 POC/法务门；否则只能做“哼唱转唱”的小范围灰度。本地跑的性能门槛见附录 A：只对话 8 GB 内存、无 GPU 可跑；唱歌建议 16 GB 内存 + 6–8 GB 显存；整首/训练更高。

## 1. 场景与模式定义

### 1.1 使用场景

| 场景 | 模式 | 用户动作 | 期望 |
|---|---|---|---|
| 日常聊天/通话 | 对话 | 打字或按住说话 | 自然、低延迟的语音回应 |
| 哄睡/生日/纪念日 | 唱歌 | 选一首歌，或输入歌词 | 角色用她的音色唱一段/一首，可保存 |
| “你哼我唱” | 唱歌 | 哼/清唱一段旋律 | 保留我的音准和节奏，换成她的音色 |
| 对唱/合唱 | 唱歌 | 用户唱一句，角色接一句 | 轮次清晰、不抢拍、不重叠 |
| 聊天中的语音彩蛋 | 唱歌（短片段，V1.5） | 说“唱一句”或点按钮 | 5–10 秒短句，异步生成，不打断聊天 |
| 内容导出 | 唱歌 | 生成后导出 | 本地音频文件，带 AI 合成标识 |

### 1.2 对话与唱歌不是同一个“开关”

| 维度 | 对话模式 | 唱歌模式 |
|---|---|---|
| 目标 | 像人一样说话 | 像歌手一样唱 |
| 输入 | 文本、语音消息 | 哼唱/清唱、选歌、歌词+旋律 |
| 输出 | 一句/一段语音 | 15 秒–4 分钟的歌曲 |
| 核心引擎 | TTS | SVC（翻唱）/ SVS（合成） |
| 音色参考 | 5–10 秒说话样本 | 20–30 秒唱歌样本（或引擎上限），或训练后的声库 |
| 音准/节奏 | 不要求 | 必须可听、可对齐、可移调 |
| 情感 | 语气、情绪标签 | 源演唱的动态/颤音/换气，或 SVS 的方差控制 |
| 延迟 | 首音 <3 秒 | 预览 15–60 秒，整首 1–5 分钟（视 GPU/引擎） |
| 失败代价 | 回退默认语音即可 | 跑调/破音/节奏错位，必须重试或降级 |
| 权利 | 声音授权 | 声音授权 + 歌曲/伴奏/歌词授权 |
| UI | 聊天页/通话页 | 独立的“唱歌工作室” |

### 1.3 目标与非目标

**目标**

- G1：用户能在“对话/唱歌”之间显式切换；切换时停止上一条音频链路，不重叠、不串音。
- G2：唱歌模式支持两种入口：哼唱/清唱转唱（V1）、授权曲库点歌（V1.5）。
- G3：唱歌输出保留目标音色，同时保留源演唱的音准/节奏/情感；或由 SVS 按乐谱生成可控的歌声。
- G4：同一角色在对话和唱歌中使用同一个“音色身份”，但允许不同的音色资产和就绪状态。
- G5：唱歌任务异步、可取消、可重试、可删除；失败有明确原因，不静默。
- G6：所有歌曲/音频按用户隔离；账号删除时清理源音频、成品、任务与声库缓存。

**非目标（V1）**

- 端到端“输入一句话就生成整首歌”的文本到歌曲（text-to-song）；
- 自动作词/作曲/编曲；专业级混音母带；
- 实时合唱/低延迟双人 K 歌；
- 专业级唇形同步/口型动画（当前只有张嘴电平）；
- 公开歌曲社区、商业发行、版权分成；
- 任意用户 5 秒说话样本直接获得专业歌手级唱歌声库。

## 2. 模式切换与交互

### 2.1 入口

1. **聊天页顶部**：`聊天 | 唱歌` 分段控件。默认聊天；点“唱歌”进入唱歌工作室。
2. **通话页**：一个“唱歌”按钮。点击后暂停通话/ASR/麦克风，进入唱歌工作室；退出后回到通话。
3. **角色页/声音设置**：显示“会说话 / 会唱歌”两个就绪徽标；可补充唱歌样本。
4. **意图识别**：用户说“给我唱首歌”时，LLM 只生成一张**确认卡片**（“要进入唱歌模式吗？”），不自动播放；用户确认后才切换。
5. **聊天中的短彩蛋**：V1.5 才做；V1 不在消息流里自动插入歌声，避免打断对话节奏。

### 2.2 状态机

```text
ChatMode
  ├─ 点“唱歌” ──────────────► SingingHome
  │                              ├─ 选歌/录音 → Configure
  │                              ├─ 生成 → Generating（异步任务）
  │                              ├─ 完成 → Preview（播放/重试/导出）
  │                              └─ 退出 → ChatMode
  └─ 通话中 ─► 点“唱歌” ─► 暂停通话/ASR/麦克风 ─► SingingHome
                                      └─ 退出 → 恢复通话（不自动继续说话）
```

状态约束：

- **同一时刻只有一条音频链路**：进入唱歌前停止 TTS、停止播放、释放麦克风；退出唱歌前停止歌曲播放。
- **生成中不可切模式**：要退出先确认“取消生成/后台继续”；后台继续时，完成后再通知。
- **通话中的麦克风**：唱歌需要录音时，先暂停通话的 VAD/ASR，避免把歌声当用户说话；建议戴耳机，防止伴奏被麦克风收进去。
- **模式不持久化为全局默认**：应用启动默认聊天；本次会话内可记住“上次在唱歌”，但不自动进入。
- **不自动切换**：意图识别只能建议，不能替用户切模式；唱歌是“进入工作室”，不是“给每条回复加歌声”。

### 2.3 线框

## 3. 功能设计

### 3.1 对话模式

直接复用 10 的方案：声音档案（5–10 秒说话样本 + 文本 + 语言）→ TTS → 通话/朗读；失败回退默认语音。对话模式不要求音准/节奏，也不加载唱歌引擎。

对话与唱歌共享：

- 同一个 `voice profile` 归属、授权记录、删除流程；
- 同一个“音色名称/头像/角色”展示；
- 同一套“AI 合成语音”标识与安全策略。

对话与唱歌不共享：

- 引擎进程（TTS 与 SVC/SVS 分开，避免互相抢 CPU/GPU）；
- 音色资产（说话参考 vs 唱歌参考/声库）；
- 任务模型（同步语音 vs 异步歌曲任务）。

### 3.2 唱歌模式的两个子模式

#### A. 哼唱/清唱转唱（V1，推荐先做）

用户提供一段**源演唱**（哼唱、清唱、带伴奏的干声），系统把音色换成目标角色，保留源音高/节奏/情绪。

流程：

```text
录制/上传源音频
  → 格式/时长/响度校验
  → 若带伴奏：人声分离（可选）
  → F0/能量/节拍提取
  → 可选：按调性做音准修正、移调
  → SVC（f0-condition）换音色
  → 与伴奏对齐/混合
  → 响度归一化、限幅
  → 试听/导出
```

优点：

- 零样本：目标音色只需要 1–30 秒参考（具体看引擎），不需要训练；
- 音准/节奏天然来自源演唱，不需要乐谱和歌词对齐；
- 情感/咬字/换气也来自源演唱，真实感最好；
- 工程链路短，V1 可落地。

局限：

- 用户必须能唱/哼；源演唱跑调，输出也会跑调（音准修正只能救一部分）；
- 哼唱没有歌词时，输出只能是“啦/啊”或根据源音素转换，不能自动变成指定歌词；
- 版权：用户上传的歌曲/伴奏仍可能侵权；产品要限制/提示。

#### B. 授权曲库点歌（V1.5）

用户选一首已授权歌曲，系统用歌词 + 旋律 + 伴奏生成目标音色的演唱。

两种实现：

1. **导唱/干声 + SVC**：曲库提供授权干声或导唱，SVC 换成角色音色，再与伴奏混合。质量稳定，接近“翻唱”，但需要干声授权。
2. **SVS 合成**：歌词 + 乐谱（MIDI/USTX）→ SVS 声库 → 歌声 → 混音。控制力最强（音高/时值/气声/颤音），但需要按音色训练声库，成本最高。

V1.5 建议先做 1（导唱 + SVC），因为可以复用 V1 的 SVC 引擎；SVS 放 V2，用于官方角色的高品质声库。

### 3.3 声音档案：说话与唱歌双就绪

同一个“音色”下存两类资产：

| 资产 | 用途 | 采集要求 | 就绪标志 |
|---|---|---|---|
| 说话参考 | TTS 对话 | 5–10 秒干净单人语音 + 逐字文本 | `speech_ready` |
| 唱歌参考 | 零样本 SVC | 20–30 秒清唱/长音/音阶，覆盖低中高音区（不超过引擎参考上限） | `singing_ready` |
| 唱歌声库（可选） | 训练后的 SVC/SVS | 3–10 分钟干声（RVC）或 30 分钟–数小时（SVS） | `studio_ready` |

规则：

- 只有说话参考时：可以对话；唱歌时提示“再录 30 秒唱歌样本”，或临时用官方默认唱歌音色。
- 唱歌参考不足会导致高音区音色断裂、气声/颤音丢失；不要用 5–10 秒说话样本硬唱高音。
- 用户可选择“我的音色”或“官方音色”唱歌；官方音色由持牌歌手录制/训练，质量与版权可控。
- 声音档案 UI 用两个徽标：`会说话`、`会唱歌`；避免用户以为“能聊天就一定能唱”。

### 3.4 唱歌参数（只放真正有用的）

| 参数 | 默认 | 说明 |
|---|---|---|
| 源输入 | 录制/上传 | 干声优先；带伴奏时做人声分离 |
| 歌词 | 可空 | 有歌词时用于对齐/纠错；哼唱可空 |
| 伴奏 | 无/上传/曲库 | 无伴奏时输出清唱；有伴奏时对齐节拍 |
| 移调 | 0 半音 | -6～+6；改变调性但不改变节奏 |
| 音准修正 | 轻 | 关/轻/强；强修正会损失颤音和情感 |
| 拍速 | 100% | 0.8–1.2；改变节奏，谨慎使用 |
| 人声/伴奏比 | 70/30 | 混音 |
| 混响 | 轻 | 房间感；不要盖过干声 |
| 输出 | WAV/MP3 | 16-bit/44.1 kHz 或 48 kHz |

**不做的假旋钮**： “情感强度 0–100”、“歌手技巧”、“颤音深度”等，除非引擎真的支持；V1 的情感来自源演唱，不能用一个滑块假装控制。

### 3.5 任务、历史与导出

- 生成是**异步任务**：`queued → running → succeeded/failed/cancelled`；前端轮询/SSE 显示进度。
- 任务可取消；取消后释放 GPU；已生成的部分不自动播放。
- 历史记录保存：源音频、成品、参数、音色、时间；可重命名/删除/重试。
- 导出：WAV/MP3 下载；文件名含角色名/歌曲名/日期；元数据标注“AI 合成”；默认不加可听水印（法务确认）。
- 分享：V1 只支持本地导出，不做公开发布；避免版权/肖像/深度伪造扩散。

## 4. 技术方案

### 4.1 两条渲染管线

```text
对话：
文本 → TTS（Genie/GPT-SoVITS）→ 语音 → 播放
       └─ 失败回退默认语音

唱歌（V1）：
源演唱 → 预处理/分离 → F0/节拍 → SVC（f0-condition）→ 混音 → 成品
                                      ▲
                                目标音色参考/模型

唱歌（V2）：
歌词 + 乐谱 → SVS 声库 → 歌声 → 混音 → 成品
```

### 4.2 引擎选型对比

| 引擎/方案 | 类型 | 音色 | 音准/节奏 | 情感 | 数据要求 | 许可证 | 判断 |
|---|---|---|---|---|---|---|---|
| Seed-VC | 零样本 SVC | 好 | 保留源演唱；f0-condition | 保留源风格；V2 可做风格转换 | 1–30 秒参考 | **GPL-3.0**，仓库已归档 | 适合 POC/能力基准；闭源分发需法务评估 |
| RVC | 训练式 SVC | 很好 | 保留源演唱 | 保留源风格 | 约 10 分钟数据，GPU 训练 | **MIT** | 适合“工作室音色”/官方声库；不是即时克隆 |
| so-vits-svc | 训练式 SVC | 好 | 保留源演唱 | 保留源风格 | 需训练 | **AGPL-3.0**，已归档 | 不建议闭源产品直接依赖 |
| DiffSinger（OpenVPI） | SVS | 取决于声库 | 乐谱级音高/时值/气声/颤音 | 方差模型可调 | 按音色训练声库 | **Apache-2.0** | 适合官方角色高品质声库/点歌 |
| ACE Studio / Synthesizer V | 商业 SVS | 很高 | 很强 | 很强 | 商业声库/授权 | 商业许可 | 质量/版权可控，按商业条款付费 |
| TTS + 变调 | 伪唱歌 | 好 | 差 | 差 | 5–10 秒 | 同 TTS | **不推荐**；机器人感明显 |
| 端到端歌曲生成 | 音乐生成 | 不可控/难克隆 | 强 | 强 | 大模型 | 复杂 | 不适合“角色音色可控”的 V1 |

结论：

- **V1 用零样本 SVC**，先做“哼唱转唱”；Seed-VC 只作为 POC 基准，是否商用取决于项目许可证与法务结论。
- **如果必须闭源分发**：优先 RVC（MIT）+ 异步训练“工作室音色”，或商业 API；不要默认打包 GPL/AGPL 引擎。
- **官方角色的高品质唱歌**：DiffSinger（Apache-2.0）训练专属声库，或商业 SVS；这是 V2 的“质量上限”。
- **不要用 TTS 变调**冒充唱歌；这是最容易做、也最容易被用户听出来的错误方案。

### 4.3 系统架构

```text
React（聊天/通话/唱歌工作室）
        │ HTTPS
Spring Boot core
  ├─ VoiceProfileService（说话/唱歌资产、就绪状态）
  ├─ SingingService（任务、参数、权限、配额）
  ├─ JobService（异步任务、进度、取消）
  ├─ MySQL：profiles / singing_jobs / songs
  └─ MinIO/本地卷：源音频、成品、伴奏、声库
        │ 内网 HTTP + token
services/singing（Python，GPU 可选）
  ├─ 预处理：ffmpeg、重采样、响度、静音裁剪
  ├─ 人声分离（可选）：Demucs/UVR
  ├─ F0/节拍：RMVPE/CREPE、beat tracking
  ├─ SVC：Seed-VC / RVC
  └─ SVS：DiffSinger（V2）
```

与 10 的 `services/voice-clone` 分开部署：

- TTS 是低延迟、CPU 可跑；SVC/SVS 是 GPU 密集、分钟级任务；混在一起会互相抢资源。
- 共享 `voice profile`、对象存储、删除编排；不共享进程。
- 单机无 GPU 时：允许 15 秒以内短片段 CPU 预览，整首提示“需要 GPU/较慢”，不要假装实时。

### 4.6 任务与资源

- 队列：按 GPU 设并发 1–2；预览任务优先，整首任务排队；队列上限防 DoS。
- 超时：15 秒片段 60 秒；整首 5 分钟；超时杀进程并清理临时文件。
- 重试：仅对 transient（GPU OOM 除外）重试 1 次；失败给可操作原因。
- 存储：源/成品/中间文件按任务隔离，成功后只保留源+成品；7–30 天清理策略可配。
- 取消：任务级取消；不要用全局“停止所有”影响其他用户。

## 5. 音色、音准、节奏、情感

### 5.1 保留音色特征

| 手段 | 说明 | 失败模式 |
|---|---|---|
| 目标音色参考 | SVC 用 20–30 秒参考（Seed-VC 上限约 30 秒；更长引擎可放宽）；建议含长音/音阶 | 参考太短/太轻/清辅音多，音色发虚 |
| 训练声库 | RVC/DiffSinger 用 3–30 分钟数据训练 | 数据脏/音域窄，高音断裂 |
| 音域覆盖 | 参考里包含低/中/高音、长音、元音 | 高音用假声/断层 |
| 共鸣/气声 | 保留目标音色的气声比例与共振峰 | 过度平滑，像“电子音” |
| 混音 | 轻压缩/混响，不压掉动态 | 过度修音，失去人味 |

### 5.2 音准

- **SVC**：源 F0 通过 `f0-condition` 注入，保留原演唱的音高走向；可整体移调，不要逐音硬修。
- **音准修正**：轻修正只拉回明显偏离；强修正会抹掉滑音/颤音/情绪，默认“轻”。
- **SVS**：音高由乐谱/音符决定，可做 portamento、vibrato、pitch drift； Mandarin 声调要与旋律结合，不能只按音高。
- **验收**：F0 RMSE（音分）、音符准确率、区间内是否破音；不要只看“听起来差不多”。

### 5.3 节奏

- **SVC**：保留源时序/咬字；与伴奏对齐时用 onset/beat 检测，不要简单拉伸整段。
- **SVS**：音符时值、辅音时长、换气位置由乐谱/歌词决定；可微调 swing/rubato。
- **伴奏**：先确定 BPM/拍号，再对齐；用户上传的伴奏与源演唱调性/拍速不一致时，提示先对齐或移调。
- **验收**：onset F1、节拍偏差、整体时长误差；不能出现“人声比伴奏慢半拍”。

### 5.4 情感表现

- **SVC**：情感主要来自源演唱（力度、颤音、气声、停顿）；换音色时尽量保留这些微动态，不要过度压缩/修音。
- **SVS**：用方差模型控制 pitch/energy/breathiness；情感预设只能是“倾向”，不是精确滑杆。
- **产品表达**：V1 的“情感”是“唱得像你/像她”，不是“把悲伤调到 80%”；不要承诺引擎做不到的精细控制。
- **验收**：ABX/MOS；是否保留换气、尾音、哭腔/笑意；是否所有歌都一个味道。

### 5.5 质量指标（POC 校准）

| 维度 | 指标 | 建议目标（相对基线） |
|---|---|---|
| 音色 | 说话人嵌入余弦相似度 / ABX | 不低于基线引擎的 90%；主观 ≥3/5 |
| 音准 | F0 RMSE（音分） | 长音 <50 cents；不出现明显破音 |
| 节奏 | onset F1 / 节拍偏差 | >0.9；人声与伴奏 <50 ms |
| 吐字 | 歌词 ASR WER | 中文 <15%（视素材） |
| 情感 | MOS / ABX | ≥3.5/5；保留换气/尾音 |
| 伪影 | MOS / 频谱检查 | 无明显金属音、爆音、断裂 |

## 6. 实现难点与更优方案

### 6.1 关键问题

| 问题 |  naive 做法为什么不行 | 更优方案 |
|---|---|---|
| TTS 不会唱 | 给 TTS 加音高/拉长，得到机器人哼唱 | 用 SVC（保留源演唱）或 SVS（按乐谱生成） |
| 5–10 秒说话样本唱不了歌 | 音域/气声/长音不足，高音断裂 | 唱歌单独采集 30–60 秒；或训练“工作室声库” |
| 零样本 SVC 许可证 | Seed-VC 是 GPL-3.0 且已归档；so-vits 是 AGPL | 闭源产品优先 RVC（MIT）+ 异步训练，或商业 API；GPL 只做 POC/法务评估 |
| RVC 需要训练 | 不能“上传 5 秒立即唱” | 分成“即时哼唱转唱（零样本）”与“工作室音色（训练）”两档 |
| 用户跑调 | SVC 会忠实保留跑调 | 轻音准修正 + 引导哼唱；强修正会损失情感，需让用户选 |
| 歌词/旋律对齐 | 直接 SVC 哼唱没有歌词；SVS 需要乐谱 | V1 允许“啦/啊”或无歌词；V1.5 曲库提供歌词+乐谱/导唱 |
| 伴奏版权 | 直接让用户上传整首歌 | 授权曲库；用户自担责提示；只做本地导出，不做公开传播 |
| 人声分离伪影 | 直接对混音做 SVC，伴奏串音 | 先分离（Demucs/UVR），或要求用户提供干声；质量差时提示 |
| Mandarin 声调 | 只按音高唱，字倒/怪声 | SVS 用声调感知的 phoneme；SVC 保留源咬字；歌词对齐检查 |
| GPU 成本/排队 | 所有请求同步跑 | 异步任务、预览优先、并发上限、CPU 短片段降级 |
| 模式切换串音 | 聊天 TTS 和唱歌同时播 | 单音频链路；进入唱歌先 stop TTS/释放麦克风 |
| 唇形同步 | 只有张嘴电平 | V1 不做专业口型；V2 用 viseme/音素驱动 |

### 6.2 方案对比（按产品目标）

| 目标 | 最优方案 | 代价 | 建议 |
|---|---|---|---|
| “她唱我哼的旋律” | 零样本 SVC | 用户要唱；引擎许可证 | V1 主路径 |
| “她唱一首完整的歌” | 授权导唱 + SVC，或 SVS 声库 | 曲库/声库成本 | V1.5/V2 |
| “官方角色专业级唱歌” | DiffSinger/商业 SVS 专属声库 | 训练数据/调优 | V2，质量上限 |
| “任何歌、任何音色、即时” | 目前没有低成本完美方案 | 质量/版权/算力 | 不要承诺 |
| “低成本、无 GPU” | 短片段 CPU SVC 或商业 API | 延迟/费用 | 预览可用，整首不现实 |

### 6.3 推荐演进

1. **V1：一个音色，两个渲染器**
   - 对话：10 的 TTS；
   - 唱歌：零样本 SVC（哼唱/清唱转唱）；
   - 显式模式切换 + 唱歌工作室；
   - 唱歌参考 30–60 秒可选；
   - 引擎 POC 对比 Seed-VC（能力）与 RVC（许可），法务定路线。
2. **V1.5：曲库与工作室音色**
   - 授权曲库 + 导唱/干声 + SVC；
   - RVC 异步训练“工作室音色”（3–10 分钟干声）；
   - 对唱/合唱、音准修正 UI、歌词对齐。
3. **V2：SVS 与商业级质量**
   - 官方角色 DiffSinger 声库；
   - 商业 SVS API 备选；
   - 唇形/表情同步、导出与分享（合规后）。

## 附录 A. 本地部署性能基线（估算）

> 以下是**量级估算**，不是实测；模型文件大小不等于运行时内存。POC 必须在目标机器上用真实音色/歌曲复测。这里的“本地”指 core + MySQL/MinIO + Python sidecar 都跑在同一台机器；只开 Electron 客户端不加载模型。

### A.1 分档配置

| 本地场景 | CPU | 内存 | GPU 显存 | 磁盘 | 体验 |
|---|---|---|---|---|---|
| 只对话（TTS） | 4 核 8 线程 | 8 GB | 不需要；有 4 GB 独显更稳 | 10 GB | 单用户流畅；首音约 1–3 秒 |
| 对话 + 短歌预览（SVC） | 6 核 12 线程 | 16 GB | 6–8 GB（RTX 3060 级） | 25–40 GB | 15–30 秒片段约 30–90 秒 |
| 对话 + 整首翻唱（SVC） | 8 核 16 线程 | 32 GB | 8–12 GB（3060 12G / 4060 Ti 16G 级） | 50 GB+ | 3 分钟歌约 2–8 分钟（3060 级更久） |
| 训练工作室声库 / SVS | 8 核 16 线程 | 32–64 GB | 12–24 GB | 100 GB+ | 训练小时级；推理仍看引擎 |

### A.2 内存拆解（估算）

| 组件 | 常驻内存 | 说明 |
|---|---|---|
| 操作系统 + 桌面 | 2–4 GB | Windows/macOS 自身 |
| Spring Boot core + MySQL + Redis + MinIO | 2–4 GB | Docker 全开偏高；单机可裁剪 Redis/MinIO |
| TTS（Genie/ONNX） | 1–2 GB | 运行时 + 一个音色模型 + Python/ONNX 开销 |
| SVC（Seed-VC 类） | 3–5 GB | 模型 + 内容编码器 + 声码器 + 音频缓冲；长片段更高 |
| 合计 | 对话 8 GB 起；唱歌 16 GB 起；舒适 32 GB | 同时跑 TTS 与 SVC 会叠加 |

### A.3 GPU 与延迟（估算）

| 任务 | GPU | 延迟量级 |
|---|---|---|
| 对话 TTS | 可纯 CPU；GPU 可选 | 首音约 1–3 秒（CPU，短句）；GPU 可更快 |
| 30 秒哼唱 SVC | 6–8 GB 显存；8 GB 更稳 | 约 20–90 秒（GPU，30–50 diffusion steps）；CPU 约 2–10 分钟 |
| 3 分钟整首 SVC | 8–12 GB 显存 | 约 2–8 分钟（3060 级）；更快 GPU 约 1–5 分钟；CPU 不建议 |
| RVC 训练工作室音色 | 8 GB+ 显存 | 10 分钟数据约 30 分钟–2 小时（3060 级，视参数/轮数） |
| DiffSinger 训练/推理 | 训练 12–24 GB；推理可 CPU | 训练小时级；推理数十秒–分钟级 |

### A.4 结论与降级

- **只做对话，要求不高**：4 核 / 8 GB / 无独显即可；这是 Genie-TTS 相对其他方案的最大优势。
- **要做唱歌，GPU 是硬门槛**：6 GB 显存只能算“能跑短片段”，8–12 GB 才比较从容；笔记本 6 GB 还要考虑散热降频。
- **没有 GPU 时**：对话照常本地跑；唱歌建议云端 GPU 或商业 API；本地 CPU 只做 15 秒以内预览，不要承诺整首。
- **省资源手段**：FP16、减少 diffusion steps（预览 4–10 步，成品 30–50 步）、缩短片段、串行任务、TTS 放 CPU 不占显存。
- **多用户**：一块 6–8 GB GPU 基本只能串行 1 个唱歌任务；多人使用要么排队，要么加 GPU/上云。
