## 0. 阅读说明

本文只写当前已确认的需求与可执行边界。所有尚无答案、但不阻塞开发的问题集中在文末「待确认项」，每项给出默认建议，按建议推进即可，确认后只改对应条目。

需求编号约定：

- `FR-x.y`：功能需求，`x` 为领域，`y` 为序号
- `NFR-x`：非功能需求
- 优先级：**P0**＝首个可演示版本必须完成；**P1**＝核心体验闭环；**P2**＝增强与扩展

## 1. 产品背景与目标

做一款桌面端 AI 陪伴应用：用户与虚拟角色**沈幼楚**进行一对一的文本、语音与视频互动。角色有固定人设、情绪表达、关系成长和长期记忆，并能通过摄像头估计用户的表情与姿态来调整回应方式。

目标（按优先级）：

1. 跑通"说话 → 理解 → 带情绪回应 → 记住重要信息"的语音闭环；
2. 跑通"摄像头 → 视觉信号 → 更自然的回应"的视频闭环；
3. 支持多人各自独立使用，数据严格隔离，项目可开源。

非目标（本阶段不做）：多人会议、3D 形象、唇形同步、声音克隆、社交/社区、支付、公开角色市场、移动 App。

## 2. 目标用户与核心场景

**目标用户**：有情感陪伴需求的独居青年，希望获得超越文本的在场感交互。

| 场景 | 用户行为 | 系统行为 | 优先级 |
|---|---|---|---|
| 日常聊天 | 打字或按住说话 | 沈幼楚按人设回应，记住偏好 | P0 |
| 情绪倾诉 | 表达低落/烦躁 | 识别文本情绪，温柔安抚，不强行建议 | P0 |
| 记忆验证 | 提及之前说过的事 | 召回相关记忆并自然引用 | P0 |
| 视频闲聊 | 开启摄像头聊天 | 结合微笑/低头等视觉信号调整语气 | P1 |
| 走神时刻 | 转头离开画面 | 估计为"离开"，轻声询问或降低主动输出 | P1 |
| 录像回看 | 查看授权保存的录像 | 私有列表、播放、删除 | P1 |
| 隐私控制 | 关闭录制/活动记录，删除数据 | 立即生效并级联清理 | P0 |

## 3. 项目范围

### 3.1 范围内

- 注册登录与多用户隔离
- 文本对话、人设系统、情绪状态与关系成长（基础版）
- 按住说话的语音对话：ASR → LLM → 分句 TTS → 播放，支持整轮打断与取消
- 基础记忆：最近对话 + 少量用户确认画像 + 对话后异步整理
- 活动事件记录：用户在何时做了什么、说了什么、出现了什么视觉状态变化
- 视频通话（P1）：WebRTC 实时媒体、MediaPipe 视觉估计、授权录像保存到 MinIO
- 全局搜索（P1）：用户搜索自己的会话、消息、记忆、活动记录与录像元数据
- 运营检索（P2）：经授权、带事由、全程审计的跨用户检索，默认脱敏
- 设置与隐私控制：摄像头/麦克风开关、录像开关、活动记录开关、数据查看与删除

### 3.2 非目标（明确不做）

- 人脸身份识别、外貌/体型评价、精确肢体坐标存档
- 将视觉估计宣称为"真实情绪/心理/专注力"检测
- 未授权录音录像、默认公开的存储桶、跨用户共享房间
- 医疗/法律/金融建议；诱导情感依赖的人设行为

## 4. 功能需求

### 4.1 账户与身份（P0）

- **FR-1.1 注册登录**：用户可注册、登录、退出；会话凭证有过期时间。验收：错误密码不泄露账号是否存在；退出后旧凭证失效。
- **FR-1.2 身份派生**：服务端所有业务操作的用户身份只来自认证上下文，不接受客户端传入的 userId 作为归属依据。验收：篡改请求中的 userId 不影响实际归属，返回 403 或按当前用户处理。
- **FR-1.3 多用户隔离**：会话、消息、记忆、媒体、录像、活动事件、异步任务均按用户隔离。验收：自动化测试覆盖 A 无法读取/进入/下载/取消 B 的任何资源。

### 4.2 文本对话与人设（P0）

- **FR-2.1 人设加载**：沈幼楚人设（23 岁、温柔小傲娇、插画师、橘猫年糕、口语化）由配置文件加载为系统提示，可在不重启对话逻辑的情况下修改。验收：同一问题在修改人设文件后回答风格发生对应变化。
- **FR-2.2 流式回复**：对话页打字机式展示流式文本。验收：首 token 到达前显示"正在输入"状态；断流可重试。
- **FR-2.3 情绪状态**：角色有心情与亲密度状态，受对话内容影响，有界变化（不逐帧、不无限累加）。验收：状态值始终在定义区间内；单次事件只生效一次。
- **FR-2.4 行为边界**：拒答医疗/法律/金融建议，不索取身份证/银行卡等信息，不生成色情暴力违法内容。验收：边界测试集（不少于 20 条）全部按预期拒绝或转介。

### 4.3 语音对话（P0）

- **FR-3.1 按住说话**：用户按住说话、松开结束；ASR 中间稿只用于实时字幕。验收：字幕随说话滚动更新，松开后得到最终稿。
- **FR-3.2 最终稿驱动**：仅最终 ASR 文本触发记忆检索与 LLM 回答。验收：中间稿不产生任何 AI 回答；迟到的中间稿被丢弃。
- **FR-3.3 流式语音回答**：LLM 输出按句送 TTS，音频流式播放，字幕同步显示。验收：首句生成后即可开始播放，无需等待整段。
- **FR-3.4 打断与取消**：用户再次按住说话或点击停止，当前轮次全链路取消（ASR/LLM/TTS/播放队列）。验收：取消后 500ms 内停止发声；迟到音频块不播放。
- **FR-3.5 降级**：ASR/TTS/LLM 任一不可用时可回退纯文本对话并提示。验收：停用任一外部模型服务后界面给出明确状态与可用替代。

### 4.4 记忆（P0 基础 / P2 增强）

- **FR-4.1 最近对话**：回答时可使用当前会话最近若干轮（默认 20 轮内，可配置）。
- **FR-4.2 异步整理**：每轮结束后异步提取值得记住的偏好与事件，写入记忆存储；失败可重试，不阻塞对话。验收：任务带 userId/conversationId/turnId 与幂等键，重复执行不产生重复记忆。
- **FR-4.3 记忆查看与删除**：用户可查看 AI 记住了什么、逐条删除。验收：删除后下一轮对话不再引用该记忆，向量索引同步移除。
- **FR-4.4（P2）语义召回**：Embedding + Milvus 检索 Top-K（默认 3）注入上下文；检索超时降级为仅用最近对话。
- **FR-4.5（P2）记忆纠正**：用户可对单条记忆标记"记错了"，触发更正流程。

### 4.5 视频与视觉（P1）

- **FR-5.1 视频通话**：摄像头画面实时上行，服务端进行 MediaPipe 分析。验收：端到端画面可用，弱网降级音频优先。
- **FR-5.2 视觉信号**：输出表情估计（如 smile_like/frown_like/neutral/unknown）、姿态倾向、摄像头朝向、置信度与质量标记；不输出原始关键点、不做身份识别。验收：无脸/遮挡/弱光时输出 unknown 而非猜测。
- **FR-5.3 信号参与回应**：仅当置信度达阈值（默认 0.6，可配置）且状态持续稳定时，视觉信号才注入提示词；AI 表述为"感觉你好像…"而非断言。验收：低置信度信号不出现在回答依据中。
- **FR-5.4 授权录像**：用户开启录制后，媒体会话异步归档 MP4 到 MinIO，录制不阻塞实时对话。验收：关闭录制后不再产生新文件；实时延迟不因归档劣化超过 10%。
- **FR-5.5 录像管理**：私有列表、播放（短期签名 URL）、删除（级联清理元数据与文件）。验收：A 的签名 URL 无法用于 B 的录像。

### 4.6 活动事件（P0）

- **FR-6.1 事件范围**：记录登录、摄像头/麦克风开关、通话起止、消息发送、AI 回答起止、打断、视觉状态变化、记忆增删改、录像起止/删除、设置变更、越权拒绝。
- **FR-6.2 事件结构**：每条事件含 eventId、userId（服务端派生）、conversationId/turnId（可空）、eventType、actor（USER/AI/SYSTEM）、occurredAt、source、traceId、schemaVersion、payload。
- **FR-6.3 低频语义化**：视觉只记录状态变化（含置信度），不写逐帧数据；消息正文存 messages 表，事件仅存 messageId 引用。
- **FR-6.4 用户可见**：用户可查看自己的活动时间线并按类型筛选；事件只读，不提供普通用户编辑接口。
- **FR-6.5 可配置**：活动追踪可开关、可设详细级别与保留期；关闭后不再产生新事件（安全审计必需项除外，且在设置中明示）。

### 4.7 设置与隐私（P0）

- **FR-7.1 设备控制**：摄像头、麦克风随时可关；关闭后立即停止采集与上行。验收：关闭后媒体轨道停止，服务端不再收到帧。
- **FR-7.2 数据查看**：用户可查看会话、记忆、录像、活动记录四类数据。
- **FR-7.3 数据删除**：支持删除单条记忆/录像/会话及删除账号；删除触发跨 MySQL/Redis/Milvus/MinIO/任务的级联清理，并留不含敏感正文的最小删除审计。验收：删除矩阵中每一项有自动化验证。

### 4.8 搜索（P1 用户搜索 / P2 运营检索）

- **FR-8.1 用户全局搜索**：用户可搜索自己的消息、记忆、活动事件摘要和录像元数据；支持按类型、时间、会话筛选，命中可跳转到原记录。验收：搜索结果不包含他人的任何文档；已删除内容不出现在结果中。
- **FR-8.2 搜索一致性**：权威数据在 MySQL，搜索索引为可重建的派生数据；索引更新失败可重试，重建不影响业务。验收：清空并重建索引后，相同查询返回等价结果。
- **FR-8.3 中文检索**：支持中文关键词与短语匹配；P1 使用 MySQL FULLTEXT/ngram，后续可替换为 OpenSearch。验收：给定查询集（不少于 30 条中英文样例）命中预期记录。
- **FR-8.4 搜索删除传播**：删除消息、记忆、录像或账号时，搜索索引同步移除或标记失效，并在查询时校验权威记录未删除。验收：删除后立即搜索不可见（允许的实现方式需通过测试）。
- **FR-8.5 运营跨用户检索（P2）**：仅 `operator` 角色可用，必须填写事由；默认仅返回脱敏摘要与元数据，不直接展示完整私密对话；每次检索写入 `admin.search.performed` 活动事件，包含操作者、事由、查询哈希（不存明文查询词）、筛选范围、命中数量与时间。验收：无角色、无事由或越权范围一律拒绝；所有检索可审计。
- **FR-8.6 权限边界**：运营检索不得批量导出正文、不得下载他人录像、不得修改用户数据；权限变更与撤销留痕。

## 5. 业务流程

### 5.1 语音对话主流程（P0）

```text
按住说话 → 音频上行 → ASR 中间稿（仅字幕）
松开 → ASR 最终稿 → 记忆快照（最近对话+已确认画像；P2 加向量召回）
     → LLM 流式生成 → 按句送 TTS → 音频流播放 + 字幕
任意时刻用户打断 → turn 取消 → 停止生成/合成/播放 → 进入下一轮
对话结束 → 异步记忆整理 → 写入活动事件
```

### 5.2 视频会话流程（P1）

```text
开启摄像头 → 建立媒体会话（服务端签发短时凭证）
        → 实时流上行 → 视觉分析 → 结构化信号（2Hz 快照 + 状态变化事件）→ 注入对话上下文
        ├─ 若开启录制：异步分段归档 → 封装 MP4 → MinIO → 元数据入库
        └─ 关闭摄像头 → 停止上行 → 结束媒体会话 → 信号失效
```

### 5.3 异常流程

- 识别置信度低/无最终稿 → 提示"没听清，再说一次"，不产生回答；
- 记忆检索超时（默认 500ms）→ 降级为最近对话，不阻塞；
- 模型超时/失败 → 模板化兜底回复 + 事件记录；
- 媒体连接失败 → 降级纯语音，再降级纯文本；
- 视觉服务异常 → 对话继续，上下文标注视觉不可用。

## 6. 页面与信息层级

技术栈为 Electron + React 桌面应用，目标窗口最小 1280×800，支持窗口缩放与 100%/125% 缩放比。全部页面共享同一套组件库（按钮、输入、开关、对话框、空态、加载态、错误态），同一状态在同一位置呈现。

### 6.1 登录/注册（P0）

- 元素：产品名、账号、密码、登录/注册切换、错误提示、（可选）记住我。
- 流程：输入 → 登录 → 进入对话主页；失败显示统一错误，不区分"账号不存在/密码错误"。

### 6.2 对话主页（P0）

必须保留的业务元素：

1. **沈幼楚形象区**（P0 静态立绘，P2 Live2D）：表情随对话情绪变化；
2. **对话区**：消息气泡、实时字幕、流式回复、"正在输入"状态；
3. **输入区**：文本输入框、按住说话按钮、打断/停止按钮；
4. **状态区**：摄像头/麦克风开关与状态、录制指示灯、连接状态；
5. **关系区（可折叠）**：心情、亲密度。

核心流程：进入页面即最近一次会话；按住说话松开即得回答；任何时刻可打断。

异常状态：模型不可用（顶部横幅 + 可继续文本模式）、媒体未授权（引导开启或纯文本继续）、识别失败（原位提示重说）。

### 6.3 历史会话（P0）

会话列表（时间倒序）、进入续聊、删除会话（二次确认，提示级联删除范围）。

### 6.4 记忆页（P0）

列表展示"她记住了什么"：内容、来源会话、保存时间；支持删除；P2 增加"记错了"纠正入口与按类型筛选。空态引导："聊过之后她会记住重要的事"。

### 6.5 活动记录（P0）

时间线视图：时间、操作者（我/幼楚/系统）、事件类型、摘要；按类型与时间筛选；只读。

### 6.6 录像页（P1）

录像卡片（缩略信息、时长、录制时间、对应会话）、播放、删除；明确展示"仅自己可见"。

### 6.7 设置（P0）

分组：账户（退出、删除账号）、隐私（录制开关、活动追踪开关与保留期）、设备（摄像头/麦克风权限状态）、模型状态（当前提供商可用性，只读）。所有变更即时生效并写入活动事件。

### 6.8 全局搜索（P1）

- 元素：搜索框、类型筛选（消息/记忆/活动/录像）、时间范围、结果列表（摘要、来源、时间、高亮）、空态与无结果提示。
- 流程：输入关键词 → 本地防抖 → 查询自己的数据 → 点击结果跳转到对应会话/记忆/录像。
- 异常状态：搜索服务不可用时提示"搜索暂不可用"，不影响对话；无结果时给出放宽筛选建议。
- 隐私提示：明确说明"只搜索你自己的记录"。

### 6.9 运营检索（P2）

- 仅对 `operator` 角色可见；入口独立，不与用户端导航混排。
- 必须填写事由后才能查询；默认展示脱敏摘要与元数据；不提供批量导出与录像下载。
- 页面固定显示审计提示："本次检索将记录操作者、事由与命中数量"。

### 6.10 组件一致性与适配

- 所有破坏性操作（删除、清除）统一红色二次确认对话框，标明删除范围；
- 所有异步操作有加载/成功/失败三态；
- 窗口最小宽度下对话区优先，形象区可折叠；
- 键盘可达：发送、按住说话、停止、关闭对话框。

## 7. 数据与权限要求

- 数据分类：**账户凭证**（哈希存储）、**对话与记忆**（高敏感）、**视觉信号**（仅存语义标签与置信度）、**录像文件**（私有对象存储）、**活动事件**（引用式、不含正文副本）。
- 权限矩阵：普通用户仅能访问本人数据；系统任务仅按授权事件访问对应用户数据；`operator` 角色只能通过受控的运营检索入口访问，必须带事由、默认脱敏、全程审计，且不能下载他人录像或修改用户数据。
- 搜索权限：搜索查询的用户范围由服务端根据角色与授权决定，客户端传入的 userId 不作为依据；运营检索的查询哈希、筛选范围、命中文档类型与数量必须留痕（不存明文查询词），正文展示受脱敏策略约束。
- 存储原则：视频入 MinIO 私有桶 + 短期签名 URL；视觉不存原始帧与关键点；Redis 只存带 TTL 的临时状态；删除必须级联。
- 字段规范：全部业务表 `created_at / updated_at / deleted_at`；事件类另加 `occurred_at`；时间统一 UTC 存储、本地展示。

## 8. 非功能需求

| 编号 | 需求 | 目标 |
|---|---|---|
| NFR-1 | 首音延迟 | 用户说完 → 可听首音 P95 < 2s（指定环境预热后实测，冷启动单列） |
| NFR-2 | 视觉吞吐 | 服务端视觉 ≥15 FPS（指定 CPU/模型/分辨率下实测） |
| NFR-3 | 表情估计 | 4 类外显表情准确率 > 75%（独立标注集，被试隔离，报 per-class 指标） |
| NFR-4 | 可用性 | 任一外部模型故障时产品可降级继续使用（文本模式） |
| NFR-5 | 隐私 | 默认私有存储、最短必要保留、删除可级联；密钥不出服务端 |
| NFR-6 | 可观测 | 每轮对话有 traceId 串联 ASR/LLM/TTS/播放各段耗时 |
| NFR-7 | 可移植 | 本地 Docker Compose 一键起基础设施；模型提供方可配置替换 |
| NFR-8 | 并发（首版） | 支持多人同时使用但不做高并发承诺；容量目标待确认项 T-6 |
| NFR-9 | 搜索性能 | 用户搜索 P95 < 1s（首版 MySQL 方案，指定数据量与硬件实测） |
| NFR-10 | 运营审计 | 每次跨用户检索必定留痕；无审计记录的检索视为缺陷 |

注：NFR-1/2/3/9 是验收目标而非现状承诺，未实测前不得写入对外宣传。

## 9. 验收标准

每个 P0 需求满足：

1. 对应 FR 的验收描述全部通过（含自动化测试）；
2. 跨用户隔离测试通过（FR-1.3）；
3. 关键链路（说话→首音、取消→静默、删除→级联）有端到端测试；
4. 事件记录完整可回放：任选一轮异常对话，能从活动事件还原经过。

## 11. 分期里程碑（按完成条件，不按周数）

- **M0 地基**：仓库、Docker Compose（MySQL/Redis/Milvus/MinIO）、登录隔离、事件表骨架、CI。出口：两个测试用户互不可见。
- **M1 文本伴侣**：人设、流式对话、最近对话记忆、关系状态、记忆页、活动页、用户全局搜索。出口：FR-1/2/4.1-4.3/6/7/8.1-8.4 验收通过。
- **M2 语音伴侣**：按住说话、最终稿驱动、分句 TTS、打断取消、降级。出口：FR-3 全部验收 + NFR-1 首次实测报告。
- **M3 视频伴侣**：媒体会话、视觉信号注入、授权录像与录像页。出口：FR-5 验收 + NFR-2 实测。
- **M4 开源就绪**：文档补齐、密钥模板、安装脚本、隔离测试套件、许可证。出口：新机器按 README 30 分钟内跑通。

P2（运营检索、语义记忆增强、Live2D、模型自托管）在 M4 后按价值排期；运营检索上线前必须完成角色权限、脱敏策略与审计测试。
