# 16 语音生成工作台：双模型卡片与三种生成模式

- 状态：草案，待评审（评审通过前不改契约正文、不写实现）
- 版本：v0.1（2026-10-30）
- 关联：[15 BYOK 落地决策](./15-byok-launch-decisions.md)、[14 语音方案定稿](./14-voice-final-design.md)、[数据与接口契约](./contracts/data-and-interface-contracts.md)、[产品需求文档](./01-product-requirements.md)
- 术语：遵循 [CONTEXT.md](../CONTEXT.md)
- 范围：前端交互与状态设计；不含代码改动。

## 0. 结论

在前端“语音生成”区域放两张模型卡：

- **CosyVoice 卡**：只生成“说话”；
- **Breeze 卡**：只生成“唱歌/哼唱”短片段（受后台开关控制）。

上方用**三段式模式切换器**（不是二元开关）选择：

1. **双模型 · 各一段**：CosyVoice 生成说话 + Breeze 生成唱歌/哼唱；
2. **单模型 · 一段**：二选一，只生成一段（CosyVoice 说话，或 Breeze 唱歌/哼唱）；
3. **单模型 · 两段**：二选一，用同一个模型生成两段（CosyVoice 两段说话，或 Breeze 两段唱歌/哼唱）。

为什么锁定类型：CosyVoice 不支持唱歌，Breeze 的产品定位是“短唱句/表演”，不是日常说话模型。V1 不提供“Breeze 说话”或“CosyVoice 唱歌”这类不可执行/不划算的组合，避免用户配出跑不通的模式。以后若产品允许 Breeze 说话，再把第二段类型扩展为“说话”。

## 1. 两张模型卡

### 1.1 卡片内容

| 区域 | CosyVoice 卡 | Breeze 卡 |
|---|---|---|
| 标题 | CosyVoice-v3-Flash · 说话 | Breeze TTS 2 · 唱歌/哼唱 |
| Key | API Key（password，只显示 last4） | API Key（password，只显示 last4） |
| 账号参数 | Workspace ID、Region | 无 |
| 音色 | 复刻音色下拉 / 克隆入口 / 就绪状态 | 克隆音色下拉 / 克隆入口 / 就绪状态 |
| 内容输入 | 说话文本、音色、情绪 | 唱句文本、音色、风格、唱歌/哼唱 |
| 结果 | 试听、重生成、发送、导出 | 试听、重生成、发送、导出 |
| 状态 | 未配置 / 校验中 / 可用 / Key 无效 / 缺音色 | 未配置 / 校验中 / 可用 / Key 无效 / 缺音色 / 后台未开放 |
| 操作 | 保存并测试 / 重新克隆 / 删除 Key | 保存并测试 / 重新克隆 / 删除 Key |
| 能力标签 | 说话 | 唱歌 · 哼唱 |

> 卡片不是“只有 Key 的表单”：每张卡 = 模型配置 + 该模型的输入区 + 该段结果。单模型两段时，被选中的卡内出现“第 1 段/第 2 段”两个子输入区。

### 1.2 卡片状态

| 状态 | 触发 | 卡片表现 | 能否生成 |
|---|---|---|---|
| `unconfigured` | 没有 Key | 输入框可编辑；提示“先配置 Key” | 否 |
| `validating` | 点“保存并测试” | 按钮 loading；输入禁用 | 否 |
| `ready` | Key/音色都可用 | 绿色状态；音色可选 | 是 |
| `invalid` | Key/Workspace 校验失败 | 红色错误；保留输入，不回显 Key | 否 |
| `missing_voice` | Key 可用但没克隆音色 | 提示“先克隆音色/选系统音色” | 否 |
| `admin_disabled` | Breeze 后台开关关闭 | 灰色锁定；提示“暂未开放” | 否 |

> Key 保存后只显示 `last4`；前端不保存明文，不在状态里回显。

## 2. 三种生成模式

### 2.1 模式定义

| 模式 | 使用的模型 | 段数 | 每段类型 | 默认内容 |
|---|---|---|---|---|
| A. 双模型 · 各一段 | CosyVoice + Breeze | 2 | 第 1 段说话（锁定 CosyVoice）；第 2 段唱歌/哼唱（锁定 Breeze） | 一段说话 + 一段唱句 |
| B. 单模型 · 一段 | CosyVoice 或 Breeze（二选一） | 1 | CosyVoice=说话；Breeze=唱歌/哼唱 | 选中的模型一段 |
| C. 单模型 · 两段 | CosyVoice 或 Breeze（二选一） | 2 | CosyVoice=说话+说话；Breeze=唱歌/哼唱 ×2 | 两段同模型内容 |

### 2.2 能力矩阵

| 模型 | 说话 | 唱歌 | 哼唱 | 备注 |
|---|---|---|---|---|
| CosyVoice-v3-Flash | ✅ | ❌ | ❌ | 主通话/语音消息 |
| Breeze TTS 2 | ❌（V1 不开放） | ✅ | ✅ | 短句；受后台开关控制 |

### 2.3 模式与卡片的关系

| 模式 | CosyVoice 卡 | Breeze 卡 |
|---|---|---|
| A 双模型 | 启用，绑定第 1 段 | 启用，绑定第 2 段 |
| B 单模型 · CosyVoice | 启用，绑定唯一段 | 禁用/折叠，保留配置 |
| B 单模型 · Breeze | 禁用/折叠，保留配置 | 启用，绑定唯一段 |
| C 单模型两段 · CosyVoice | 启用，绑定两段 | 禁用/折叠 |
| C 单模型两段 · Breeze | 禁用/折叠 | 启用，绑定两段 |

卡片不因模式切换而丢失 Key/音色；只是“当前未使用”。

## 3. 页面结构

```text
┌─ 语音生成 ──────────────────────────────────────────┐
│ 模式  [双模型·各一段] [单模型·一段] [单模型·两段]   │
│ 单模型时：[CosyVoice 说话] [Breeze 唱歌]            │
│                                                     │
│ ┌─ CosyVoice 卡 ─────────────┐ ┌─ Breeze 卡 ─────────────┐
│ │ Key/Workspace/Region [测试]│ │ Key [测试]              │
│ │ 音色 [沈幼楚 v] [克隆]     │ │ 音色 [沈幼楚 v] [克隆]  │
│ │ ─ 输入：说话 ─             │ │ ─ 输入：唱歌/哼唱 ─     │
│ │ 文本 [..................]  │ │ 文本 [................] │
│ │ 情绪 [温柔 v]              │ │ 风格 [温柔 v] 方式[唱歌]│
│ │ 结果 [▶][重试][发送][导出] │ │ 结果 [▶][重试][发送][导出]│
│ └────────────────────────────┘ └─────────────────────────┘
│                                                     │
│ [生成两段]  或  [生成]        [取消]                │
│ 状态：等待/生成中/部分成功/完成                      │
└─────────────────────────────────────────────────────┘
```

- 单模型一段：只显示被选中卡片的内容输入区；另一张卡折叠为“当前模式未使用”。
- 单模型两段：被选中卡片内显示“第 1 段/第 2 段”两个输入区；另一张卡折叠。
- 页面位置建议：**设置 → 语音服务 → 语音生成**；聊天页“生成语音”快捷入口可跳到同一页/弹层。
- 未使用的模型卡折叠为一条“当前模式未使用”的窄条，点击可展开配置，避免布局跳动。
- 结果跟随各自卡片/段落展示；不另开结果页。

## 4. 交互状态

### 4.1 页面级状态

| 状态 | 含义 | 可操作 |
|---|---|---|
| `loading` | 读取 Key/音色/开关 | 骨架屏 |
| `setup_required` | 两家都未配置/不可用 | 只能配置卡片 |
| `idle` | 至少一个模式可生成 | 编辑、切换模式、生成 |
| `validating` | 正在校验某张卡 | 可编辑其他区域；生成禁用 |
| `generating` | 有段在生成 | 禁止切模式/改卡片；可取消 |
| `partial` | 部分段成功、部分失败 | 重试失败段、导出成功段 |
| `done` | 全部成功 | 重生成、发送、导出 |
| `cancelled` | 用户取消 | 重新生成 |

### 4.2 段落级状态

`empty → ready → queued → generating → succeeded / failed / cancelled`

- 每段独立显示状态；双模型/两段模式允许一段成功一段失败。
- 失败段显示可操作原因：Key 无效、音色未就绪、Breeze 未开放、限流、超时。
- “重试”只重跑失败段；“全部重生成”重置全部。

### 4.3 卡片校验

- 输入 Key 后点“保存并测试”，不自动每次输入都校验。
- 校验中按钮 loading；成功变 `ready`；失败 `invalid`，保留输入但清空明文显示。
- 音色未就绪时 `missing_voice`；生成按钮禁用并提示“先克隆音色”。

## 5. 切换逻辑

### 5.1 模式切换器

用**三段式 segmented control**，不是二元开关：

```text
[双模型 · 各一段] [单模型 · 一段] [单模型 · 两段]
```

- 单模型模式下，再显示模型二选一：`[CosyVoice 说话] [Breeze 唱歌]`。
- 双模型模式不显示模型二选一，两张卡都启用。

### 5.2 切换规则

1. **生成中禁止切换**：模式切换器禁用；提示“先取消生成”。
2. **校验中允许切换**：但目标模式若依赖未校验卡，生成按钮禁用。
3. **切换不销毁草稿**：每种模式/模型/段落的文本、音色、风格分别存草稿；切回时恢复。
4. **首次切到目标模式**：
   - 双模型 → 单模型：优先带入“最后聚焦”的那张卡的文本；另一段留在双模型草稿里。
   - 单模型 → 双模型：若双模型草稿存在，恢复；否则把当前文本放入对应模型的段。
   - 单模型一段 → 单模型两段：当前文本复制到第 1 段，第 2 段空；CosyVoice 两段都是说话，Breeze 两段默认唱歌。
   - 单模型两段 → 单模型一段：保留第 1 段；第 2 段草稿保留，切回时恢复。
5. **切换模型（单模型内）**：文本保留；类型按新模型能力重映射（CosyVoice=说话；Breeze=唱歌/哼唱）；提示“文本将作为唱词/说话稿”。
6. **切换时停止播放**：避免两段音频重叠。
7. **不可用模式**：
   - Breeze 后台关闭 → “双模型”“单模型 Breeze”“单模型两段 Breeze”选项禁用/隐藏；当前若是这些模式，自动切到 CosyVoice 单段，并提示“唱歌草稿已保留”。
   - Breeze 未配置 Key → 选项可选，但生成禁用，卡片显示“先配置 Key”。
   - CosyVoice 未配置 → 双模型禁用；单模型 CosyVoice 禁用；若 Breeze 可用，默认切到 Breeze 单段。
   - 两家都不可用 → `setup_required`，模式切换器禁用。

### 5.3 默认模式选择

页面打开时按可用性决定默认：

1. CosyVoice 可用 + Breeze 可用 → 双模型；
2. CosyVoice 可用、Breeze 不可用 → 单模型 CosyVoice 一段；
3. CosyVoice 不可用、Breeze 可用 → 单模型 Breeze 一段；
4. 都不可用 → `setup_required`。

> 默认值只决定初始展示，不覆盖用户上次选择；若上次选择已不可用，再回退。

## 6. 生成流程

### 6.1 前置校验

按模式检查：

- 双模型：两卡都 `ready`、两段文本非空、两段音色已选；
- 单模型一段：选中卡 `ready`、文本非空；
- 单模型两段：选中卡 `ready`、两段文本都非空；
- Breeze 相关模式：后台开关开启、Breeze Key/音色可用；
- CosyVoice 相关模式：Key/Workspace/Region/音色可用。

不通过时：生成按钮禁用，段落下方显示具体原因与“去配置/去克隆”链接。

### 6.2 生成与并发

- 双模型：CosyVoice 与 Breeze 并行；两段独立。
- 单模型两段：
  - CosyVoice：默认顺序生成，避免同 Key 并发限流；可配置。
  - Breeze：两个异步任务顺序提交，避免占满套餐并发；可配置。
- 每段有独立 `requestId/jobId`；批量有 `batchId` 用于聚合状态。
- 取消：
  - 双模型：取消整批，或单段取消；
  - 单模型两段：取消整批，或当前段；已完成的保留。

### 6.3 结果

- 成功段：播放、重生成、发送到聊天、导出（唱句导出带 AI 标识）。
- 失败段：错误原因 + 重试。
- 部分成功：允许发送成功段；不因失败段阻塞。
- 双模型结果可对比试听（两个播放器独立，不自动混音）。

## 7. 后端契约（草案）

新增批量端点，避免前端自己拼两家调用：

```http
POST /ai-girl/voice/generate
{
  "mode": "dual",
  "segments": [
    {"id":"s1","provider":"cosyvoice","type":"speak","text":"...","voiceProfileId":"...","emotion":"gentle"},
    {"id":"s2","provider":"breeze","type":"sing","text":"...","voiceProfileId":"...","style":"gentle"}
  ]
}
```

响应：

```json
{
  "batchId": "gen_...",
  "segments": [
    {"id":"s1","status":"queued"},
    {"id":"s2","status":"queued"}
  ]
}
```

查询：

```http
GET /ai-girl/voice/generate/{batchId}
```

```json
{
  "batchId": "gen_...",
  "status": "partial",
  "segments": [
    {"id":"s1","status":"succeeded","audioUrl":"...","durationMs":4200},
    {"id":"s2","status":"failed","errorCode":"SING_DISABLED","message":"唱句功能未开启"}
  ]
}
```

后端校验：

- `dual`：必须 2 段，provider 为 `cosyvoice`+`breeze`，type 为 `speak`+`sing|hum`；
- `single`：1 段，provider/type 匹配；
- `single_two`：2 段，同一 provider；CosyVoice 两段都 `speak`；Breeze 两段都 `sing|hum`；
- Breeze 开关关闭 → 403 `SING_DISABLED`；
- 凭据/音色不可用 → 对应错误码；
- 防重复提交：前端按钮 loading + 幂等键。

> 现有 `/ai-girl/voice/speak`、`/sing` 继续服务聊天/通话单段场景；工作台用 `/generate` 聚合。

## 8. 异常与文案

| 情况 | 展示 |
|---|---|
| Breeze 后台关闭 | 卡片“暂未开放”；模式选项禁用；“唱歌草稿已保留” |
| Breeze Key 未配置 | 卡片“未配置 Key”；生成禁用；“去配置” |
| CosyVoice Key 无效 | 卡片“Key 无效”；生成禁用；“重新填写” |
| 音色未克隆 | 卡片“缺音色”；“去克隆” |
| 生成中切换模式 | 提示“请先取消当前生成” |
| 一段失败 | “第 2 段失败：唱句功能未开启”；[重试] |
| 两段都失败 | 批量失败；可重试全部 |
| 文本为空 | 段落下提示；生成禁用 |
| 文本过长 | 提示分段/缩短；不静默截断 |

## 9. 验收

| ID | 场景 | 期望 |
|---|---|---|
| AC-GEN-1 | 双模型、两卡可用、两段文本 | 生成两段；可分别播放/发送 |
| AC-GEN-2 | 单模型 CosyVoice | 只显示说话段；生成一段 |
| AC-GEN-3 | 单模型 Breeze | 只显示唱句段；生成一段 |
| AC-GEN-4 | 单模型两段 CosyVoice | 两段说话；顺序生成 |
| AC-GEN-5 | 单模型两段 Breeze | 两段唱句；顺序生成 |
| AC-GEN-6 | 双模型一段失败 | 部分成功；失败段可重试；成功段可发送 |
| AC-GEN-7 | 生成中切模式 | 禁止；提示先取消 |
| AC-GEN-8 | 切换模式/模型 | 草稿保留；不丢文本 |
| AC-GEN-9 | Breeze 开关关闭 | 相关模式禁用；自动回退 CosyVoice 单段；草稿保留 |
| AC-GEN-10 | 未配置 Key/音色 | 生成禁用；明确原因 |
| AC-GEN-11 | 两段都成功 | 可全部发送/导出；唱句导出带 AI 标识 |
| AC-GEN-12 | 取消 | 已完成段保留；未完成段取消；可重生成 |

## 10. 待确认

1. 工作台入口放“设置 → 语音服务”，还是聊天页“+ → 语音生成”？建议前者，聊天页只放快捷入口。
2. 双模型模式下，Breeze 第二段是否允许“说话”类型？V1 建议只唱歌/哼唱，保持能力矩阵简单。
3. 单模型两段默认顺序还是并行？建议顺序，避免限流/并发；可加“并行”高级开关。
4. 切换模式时，双模型 → 单模型带入哪一段？建议“最后聚焦的卡片”；是否需要在切换时弹选择框？
5. 部分成功是否允许直接发送成功段？建议允许，并保留失败段重试。
6. 唱句导出 AI 标识是否沿用 15 的“可听 + 元数据 + 文件名”？建议沿用。
