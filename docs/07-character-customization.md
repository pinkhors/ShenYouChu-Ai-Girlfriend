# 女友角色设定（Character Studio）功能设计

- 版本：v1.0
- 状态：P0 已实现；P1 核心项已实现（草稿自动备份、角色卡统计、复制立绘等未做）；P2 未实现；V4/V5 已在本机 MySQL 8 执行并通过 API 冒烟；Electron 视觉回归与 IndexedDB 迁移待本机验证
- 关联：[产品需求文档](./01-product-requirements.md) FR-2.1 / FR-2.3 / FR-2.4 / FR-2.5 / FR-2.6、[数据与接口契约](./contracts/data-and-interface-contracts.md) §2.2–2.5、[开发规范](./03-development-standards.md)
- 范围：桌面端角色的创建、编辑、保存、切换，以及和现有聊天、形象、记忆、通话、设置的衔接

## 0. 结论摘要

把“沈幼楚”从写死的单例，升级为**角色卡（Character）**：

1. **角色是一等对象**。用户可保存多个角色；每个角色有独立的形象、性格、家庭背景，以及独立的会话、记忆和心情/亲密度。
2. **官方角色人设只读，自定义角色可编辑**。沈幼楚保留为默认角色和品牌锚点；她的本机形象可以继续调整，但要改人设就“复制为我的角色”，避免官方人设被改坏。
3. **三类设定 + 两个基础层**。基础身份（名字、年龄、一句话介绍）→ 形象 → 性格 → 家庭背景；另有一层不可关闭的安全边界。
4. **切换 = 换“当前角色”，每个角色只有一条会话**。用户与角色严格一对一；创建角色时自动生成唯一会话，不能手动新建；换人就是切到她的那一条会话。
5. **自定义角色定义存服务端，立绘存本机**。自定义角色的人设与形象参与提示词和跨设备展示，必须服务端持久化；官方角色的人设只读，形象是本机覆盖；AI 立绘体积大，继续本机 IndexedDB，按“用户 + 角色”隔离。

这五个决策决定了后面的界面、数据和迁移方案。

## 1. 背景、目标与边界

### 1.1 现状

- 角色只有一个：沈幼楚。人设来自 `characters.persona_config`，由 `PersonaService` 拼成系统提示词。
- 前端多处写死“沈幼楚”和同一份 `avatar`：`App.tsx`、`ChatView.tsx`、`ConversationSidebar.tsx`、`CallView.tsx`、`AvatarEditor.tsx` 等。
- 形象（捏脸参数）与立绘都只存在本机，按 `userId` 隔离；没有多角色概念。
- 后端其实已经为多角色留了口子：`conversations.character_id`、`user_character_states(user_id, character_id)`、`CharacterController` 列表接口都存在，只是前端永远用默认角色。

### 1.2 要解决的问题

- 用户只能接受一个人设，不能按自己的偏好塑造陪伴对象。
- 形象、性格、家庭背景三者没有形成“一个人”的整体，改外观不会改变说话方式，改人设也不会影响展示。
- 没有保存、命名、切换、复制、归档多套角色的入口。

### 1.3 目标

- 用户可以在 3 分钟内从模板或空白创建一个角色，并完整保存。
- 用户可以在任意页面 2 次点击内切换当前角色。
- 每个角色的对话、记忆、关系状态、立绘互不串台。
- 角色设定能真实影响对话风格，而不是只改一张皮。
- 现有单角色用户的数据、会话、形象不丢失。

### 1.4 非目标

- 不做公开角色市场、角色分享、社区排行。
- 不做真实人物上传/换脸，不支持未成年人角色。
- 不做 3D/Live2D 角色编辑器（P2 以后）。
- 不做每个角色独立音色（P2；首版音色仍为全局设置）。
- 不把角色设定开放给运营检索或跨用户检索。

### 1.5 设计原则

1. **先看到，再选择**：每个抽象选项都要有可视或可读的结果预览。
2. **默认即完整**：所有字段都有合理默认值，只有名字必填；用户可以一路“下一步”快速建完。
3. **一次只改一件事**：创建走四步，编辑走标签页；不在一个屏幕堆 50 个控件。
4. **官方是锚点**：沈幼楚永远是默认和兜底，不因用户自建角色而消失。
5. **边界不可协商**：所有角色共用同一套安全边界，不能通过“性格”或“家庭背景”绕过。

## 2. 核心概念与信息架构

### 2.1 概念

| 概念 | 定义 | 说明 |
|---|---|---|
| 角色卡 Character | 一个可被选择、编辑、保存的女友 | 含身份、形象、性格、家庭背景 |
| 官方角色 | 平台内置、人设只读的角色 | 首版只有沈幼楚；本机形象可覆盖 |
| 自定义角色 | 用户创建、归用户所有、可编辑 | 最多 12 个（含归档） |
| 当前角色 Active Character | 用户此刻“正在陪伴”的角色 | 全局唯一，服务端保存 |
| 角色绑定会话 | 创建时指定角色、之后不可换人的会话 | `conversations.character_id` |
| 角色模板 Template | 新建时的起点（不是已保存角色） | 空白、温柔邻家、傲娇青梅等 |

### 2.2 关系

```text
用户 ──1:N── 角色卡 ──1:N── 会话 ──1:N── 消息
                 │                 └──1:N── 记忆
                 ├──1:1── 心情/亲密度（user_character_states）
                 └──1:N── 本机立绘（IndexedDB，按用户+角色隔离）

用户 ──1:1── 当前角色（user_preferences.active_character_id）
```

关键约束：

- 一个用户同时只有一个当前角色。
- 一个会话只属于一个角色，**不允许中途换角色**；否则人设、记忆、关系状态都会失真。
- 删除角色分“归档”和“彻底删除”；彻底删除才级联会话与记忆。

角色生命周期：

```text
草稿（只在编辑器内存）
  │ 保存
  ▼
已保存角色 ──设为当前──▶ 当前角色
  │                         │
  │◀────── 恢复 ──── 归档 ◀─┘（归档当前角色时自动回退官方）
  │
  └──彻底删除──▶ 级联清理会话/消息/记忆/状态/本机立绘
```

**保存与切换是两个独立动作**：保存只落库，不会自动改变当前角色；只有“保存并切换”或切换器才会改变当前角色。

### 2.3 导航调整

现有左侧导航：聊天 / 形象 / 记忆 / 活动 / 设置。

改为：**聊天 / 角色 / 记忆 / 活动 / 设置**。

- “形象”升级为“角色”页：角色中心 + 角色编辑器；原来的捏脸/立绘成为编辑器里的“形象”标签。
- 左侧栏顶部在用户头像下方增加**当前角色迷你头像**，点击打开切换器；这样在聊天、记忆、设置任何页面都能换人。
- 聊天页顶部、会话列表、角色卡三处都能打开同一个切换器，行为一致。

## 3. 角色模型与选项范围

一个角色由四层组成：

```text
基础身份（必填的名字 + 年龄 + 可选一句话）
  ├─ 形象（外观 / 发型 / 服饰）
  ├─ 性格（主性格 + 调味标签 + 表达方式）
  └─ 家庭背景（成长环境 / 家庭关系 / 经济状况 + 可选补充）
固定边界（所有角色共享，不可编辑）
```

### 3.1 基础身份

| 项目 | 控件 | 范围 | 默认 | 说明 |
|---|---|---|---|---|
| 名字 | 单行输入 | 2–12 字符；不能换行；不能与自己的角色重名；不能使用“沈幼楚” | 无（必填） | 显示在角色卡、聊天头部、会话列表 |
| 年龄 | 数字步进器 / 滑杆 | 18–45 的整数 | 23 | 仅支持成年角色；< 18 直接拦截 |
| 一句话介绍 | 单行输入 | 0–40 字符 | 空 | 角色卡副标题；也会进入提示词，帮助模型抓住她的生活感 |

示例介绍文案：

- “独居插画师，养了一只叫年糕的橘猫。”
- “在便利店上夜班，白天永远睡不醒。”
- “刚搬来这座城市，路痴但嘴硬。”

### 3.2 形象

形象分“捏脸”和“立绘”两种来源，二者共用同一份角色卡。每个角色可在编辑器里选择“自动 / 立绘 / 捏脸”：自动时有立绘用立绘，没有则回退矢量捏脸；选择“捏脸”时即使有立绘也显示矢量形象。角色卡、切换器、会话列表、聊天和通话统一遵循这个选择。

对官方角色，形象调整只在本机生效；对自定义角色，形象参数随角色保存到账号。这样既保留老用户已经调好的沈幼楚，也让新角色的形象可以跨设备。

#### 3.2.3 呈现方式

- **左侧固定预览**：3:4 半身像，实时跟随所有参数；切换标签不丢预览。
- **右侧分组**：轮廓 / 五官 / 发型 / 服饰四组；默认只展开“发型”和“服饰”，其余折叠，减少首屏压力。
- **色卡必须带文字**：悬停/聚焦显示颜色名，选中打勾；不能只靠颜色区分（色弱可辨）。
- **图形卡**：发型和服饰用简单轮廓图 + 名称 + 一行描述，而不是一排文字按钮。
- **快捷模板**：温柔 / 清冷 / 元气 / 知性四套现有预设保留，放在最上方；点选只改形象，不改性格，并明确标注“仅应用外观”。
- **随机与恢复默认**：提供“随机”和“恢复默认”两个快捷动作；随机后可直接再调参数，或恢复默认。
- **立绘子标签**：形象标签内再分“捏脸 / 立绘”。捏脸用于调参；立绘用于导入/生成该角色的表情差分。立绘存在时，角色卡、切换器、会话列表、聊天默认用立绘；用户可在“形象来源”中强制切回捏脸。

#### 3.2.4 新增字段与兼容

在现有 `AvatarConfig` 上新增：

```ts
outfitStyle: 'casual' | 'knit' | 'campus' | 'commute' | 'home' | 'vintage' | 'sporty'
```

- 旧数据没有该字段时，`normalizeAvatar` 回退 `casual`。
- 发型新增 `ponytail`（高马尾）和 `short`（利落短发）；旧数据不受影响。
- 渲染层 `GirlfriendAvatar` 增加对应的发型/服饰路径；如果短期无法补齐，先只开放已有 5 种发型，字段和选项表保持可扩展。

### 3.3 性格

性格分两层：**主性格**决定她怎么理解关系，**调味标签**决定她怎么把这种性格说出来。

#### 3.3.1 主性格（必选 1 个）

| ID | 标签 | 核心气质 | 关心方式 | 冲突/生气方式 | 说话特征 |
|---|---|---|---|---|---|
| gentle | 温柔治愈 | 先接住情绪，再慢慢说 | 细节照顾、留白、不逼问 | 先软下来，说自己的感受，不翻旧账 | 语气缓、少感叹号、句子偏短 |
| tsundere | 傲娇嘴硬 | 关心藏在反话里，被戳穿会害羞 | 嘴上嫌弃、行动照顾 | 别扭一会儿，然后直接说“我其实在意” | 反问、省略号、口是心非 |
| lively | 活泼元气 | 主动找话题，情绪有感染力 | 逗你开心、拉你出门、分享小事 | 当场说开，不冷战 | 短句、拟声词、感叹号 |
| cool | 清冷慢热 | 话少但认真，熟悉后直球 | 安静陪着、记住细节、少说多做 | 先沉默消化，再给一句很直的回应 | 短句、留白、少语气词 |
| intellectual | 知性从容 | 讲逻辑也讲感受，喜欢分享见闻 | 帮你拆问题、给新角度 | 讲道理但不居高临下，会先承认情绪 | 结构清楚、爱举例、不说教 |
| lazy | 慵懒松弛 | 节奏慢，爱赖床，但不黏人 | 一起躺平、用玩笑化解 | 懒得吵，直接说“我现在不想说这个” | 慢悠悠、拖长音、爱撒娇 |
| reliable | 认真可靠 | 记得细节，会提醒和规划 | 具体地帮你安排、提醒吃饭睡觉 | 认真沟通，给方案，不控制 | 条理清楚、少夸张、行动派 |
| whimsical | 古灵精怪 | 爱开玩笑、脑洞大 | 用奇怪比喻逗你、制造小惊喜 | 先搞笑缓和，再认真道歉 | 跳脱、比喻多、爱接梗 |

#### 3.3.2 她会怎么说话（示例）

预览区的示例台词由**本地模板**生成，不调用模型，所以点选即时更新；实际聊天仍由 LLM 生成。示例的作用是让用户感知“这个性格是什么味道”。

| 主性格 | 你说“今天好累” | 你夸“你今天真好看” | 你提到“周末和女同事吃饭” |
|---|---|---|---|
| 温柔治愈 | “先别撑着了，坐下，我给你倒杯水。今天想先说哪一件？” | “……你这样说我有点不知道看哪里。那，只准今天多看一会儿。” | “听起来是正常的同事聚餐。你会去吗？我想听你讲讲。” |
| 傲娇嘴硬 | “谁让你又硬撑。……过来，靠一会儿，就一会儿。” | “哼，今天才发现？……算了，你眼光还行。” | “哦，女同事啊。……我没说不可以，但你得跟我说说都有谁。” |
| 活泼元气 | “收到！现在启动‘下班回血计划’：先喝水，再瘫十分钟，然后跟我说今天最离谱的一件事。” | “嘿嘿，被你发现了！那我今天要多笑两下，给你赚到。” | “哇，聚餐！好吃的多吗？……不过你要是只顾着聊天，我会有点小意见哦。” |
| 清冷慢热 | “嗯。先休息。想说的时候我在。” | “……谢谢。你也是，今天很好看。” | “同事聚餐很正常。你去吧，回来跟我说一声。” |

#### 3.3.3 调味标签（可选 0–2 个）

主性格是骨架，调味标签是语气。最多选 2 个；硬互斥项（独立/黏人）置灰，软冲突项（慢热 + 高主动/黏人）给出提示但不阻止。

| affectionate | 爱撒娇 | 更常说想你、要抱抱；会看场合 | 无 |
| slow-warm | 慢热 | 初期客气，熟悉后反差大 | 与“主动程度：高”同选时提示；与“黏人”同选时也提示 |
| teasing | 爱吐槽 | 轻松调侃，不拿痛处开玩笑 | 无 |

#### 3.3.4 表达方式（细调）

| 项目 | 控件 | 选项 | 默认 | 影响 |
|---|---|---|---|---|
| 表达强度 | 三档分段 | 克制 / 自然 / 明显 | 自然 | 情话、感叹号、情绪外露的程度 |
| 主动程度 | 三档分段 | 慢热 / 适中 / 主动 | 适中 | 主动开场、追问、提出一起做事的频率 |
| 对你的称呼 | 预设 chips + 自定义 | 你 / 亲爱的 / 笨蛋 / 宝贝 / 哥哥 / 自定义 1–6 字 | 你 | 逐字进入提示词；要求不每句重复 |
| 自称 | 预设 chips | 我 / 人家 / 本小姐 / 姐姐 / 自己的名字 | 我 | 逐字进入提示词；避免每句都带 |
| 在意程度 | 三档分段 | 低 / 中 / 高 | 中 | 吃醋的表达强度；高也只表达在意，不查岗、不威胁 |

**边界保护**：自定义称呼和自称会做长度与换行校验，并以“引号内的字面值”进入提示词；它们不能改变行为边界。

#### 3.3.5 呈现方式

- **先看台词，再看选项**：8 张主性格卡，每张显示标签、两个关键词、一句示例台词；选中后卡片展开“关心方式 / 生气方式”。
- **细调在下方**：表达强度、主动程度用三段分段控件；称呼/自称用 chips；在意程度放“更多细节”折叠区。
- **实时试聊**：右侧/左侧预览区固定 4 个气泡（你说累、你夸她、你提到别人、她主动开场），随主性格、调味标签、强度、称呼即时更新。标注“风格示例，实际对话由模型生成”。
- **性格摘要**：预览卡底部生成一句话，例如“温柔治愈 + 小傲娇：先接住情绪，再用反话关心你。”

### 3.4 家庭背景

家庭背景用于给角色“生活质感”，不是给用户做现实评判。每个选项都写成**表达倾向**，不写“某种家庭一定怎样”。

#### 3.4.1 成长环境（5 选 1）

| ID | 标签 | 她的来处 | 对她的影响 |
|---|---|---|---|
| small-town | 小城慢生活 | 熟人社会、节奏慢、离自然近 | 重视人情与小确幸；对大城市的喧嚣既好奇又谨慎 |
| city | 都市长大 | 独立、见多识广、习惯快节奏 | 边界感强、适应快；偶尔怀念被照顾的感觉 |
| county | 乡镇/县城 | 家庭纽带强、生活务实 | 节俭、看重承诺；对“被认真对待”很敏感 |
| overseas | 异乡/海外 | 跨文化成长、搬家经历 | 独立又要归属感；偶尔用另一种语言或视角表达 |
| mobile | 经常搬迁 | 因家庭工作多次换城市 | 适应力强但不易交心；对“稳定”有隐秘渴望 |

#### 3.4.2 家庭关系（5 选 1）

| ID | 标签 | 她的家庭 | 对她的影响 |
|---|---|---|---|
| close | 亲密支持 | 和父母像朋友，遇事会商量 | 安全感足，善于表达关心；也会自然地问你的家人 |
| polite | 平淡客气 | 关心彼此但少深谈 | 不太主动说心里话；需要被温和地引导 |
| apart | 聚少离多 | 父母忙碌或异地，习惯自己扛 | 独立、不擅长求助；被照顾时会有点不知所措 |
| single-parent | 单亲/重组 | 家庭结构变化，早熟 | 对承诺敏感、重视稳定；不喜欢被比较 |
| strained | 关系紧张 | 与家人有隔阂，渴望被理解 | 面对冲突会谨慎、容易先退让；不卖惨、不指责家人 |

> 文案约束：不把单亲/重组写成“缺陷”，不把经济条件写成“可怜”或“势利”。角色可以提到家庭，但不主动卖惨、不贬低家人、不把家庭当成索取理由。

#### 3.4.3 经济状况（4 选 1）

| ID | 标签 | 她的日常 | 对她的影响 |
|---|---|---|---|
| tight | 拮据 | 精打细算，对价格敏感 | 收到礼物会不安，更看重心意；不愿占便宜 |
| ordinary | 普通 | 收支平衡，务实 | 偶尔为喜欢的东西小小奢侈；对朋友大方 |
| comfortable | 小康 | 生活从容，愿意为体验花钱 | 重视生活质量；不炫耀，也不理所当然 |
| wealthy | 优渥 | 物质无忧，见过好东西 | 对“被当成理所当然”敏感；更看重真诚与边界 |

#### 3.4.4 “这样的她”摘要

三个选择完成后，编辑器实时生成一段 2–3 行的摘要，帮助用户确认“这些选项合起来是什么人”：

> 她在都市长大，和父母关心彼此但少深谈，经济普通。
> 这让她独立、务实，不太主动说心里话；被认真对待时会记很久。

摘要同时作为角色卡的“背景标签”来源（例如“都市 · 平淡 · 普通”）。

#### 3.4.5 补充设定（可选）

- 控件：单行输入，0–60 字符，禁止换行。
- 示例：“怕打雷”“家里有一只老狗”“每年冬天回外婆家”。
- 作用：只补充生活细节，不覆盖行为边界；提示词中用固定包装包裹，并放在边界之前。
- 校验：超长截断提示；出现换行/控制字符直接拒绝。

- 立绘：复用现有 PortraitStudio，但标题改为“林晚的立绘”，导入/生成都只作用于当前角色。
- 形象来源：捏脸面板顶部提供“自动 / 立绘 / 捏脸”三选一；立绘未导入时“立绘”禁用；选择结果按 user+character 存本机，并同步影响角色卡、切换器、会话列表、聊天、通话与编辑器预览。
- 立绘或聊天主视觉存在时，列表与聊天将使用图片；没有时显示矢量形象。若只导入了聊天主视觉，列表头像也会回退使用主视觉。
- 生成立绘的提示词由当前角色的身份 + 形象自动拼装，不再使用写死的沈幼楚提示词（P1）。

#### 4.3.3 性格标签

- 上半：8 张主性格卡（2 列 × 4 行）。
- 中部：调味标签 chips（最多 2 个，互斥置灰）。
- 下半：表达强度、主动程度、称呼、自称、在意程度。
- 右侧/下方：四场景试聊气泡 + 性格摘要。
- 所有控件本地即时更新，不发请求；只有“保存”才落库。

#### 4.3.4 家庭标签

- 三个维度各一行：成长环境 / 家庭关系 / 经济状况。
- 每个维度用 4–5 个胶囊按钮；选中后下方说明卡切换为该选项的“她的来处 / 对她的影响”。
- 底部“这样的她”摘要卡实时更新。
- 补充设定单行输入 + 字数计数。
- 固定提示：“这些设定只影响她的表达与生活细节，不代表对任何群体的判断。”

### 4.4 新建流程

```text
[+ 新建女友]
   ↓
选择起点（空白 / 温柔邻家 / 傲娇青梅 / 元气学妹 / 清冷学姐 / 复制沈幼楚）
   ↓
步骤 1 认识她：名字 + 年龄 + 一句话
   ↓
步骤 2 她的样子：形象（可跳过，用模板默认）
   ↓
步骤 3 她的性格：主性格 + 调味 + 表达（可跳过，空白模板默认温柔/自然/适中）
   ↓
步骤 4 她的来处：家庭三项 + 补充（可跳过，空白模板默认都市/平淡/普通）
   ↓
[保存并创建] → 角色中心，新卡高亮 + “设为当前并聊天 / 稍后再说”
```

流畅性设计：

- 每一步都有默认值，只有名字必填；用户可以一路“下一步”。
- 步骤条可点击回退；前进只校验当前步（名字/年龄）。
- “使用默认”链接在每步右上角，一键填默认。
- 创建成功后不强制切换当前角色；给出“设为当前并聊天”主按钮，避免用户只是保存却被换人。
- 全程无嵌套弹窗；只有模板选择是一个轻量弹层/整页。

### 4.5 保存、切换、删除的状态规则

| 动作 | 入口 | 行为 | 失败/未保存处理 |
|---|---|---|---|
| 保存 | 编辑器底部 / Ctrl/Cmd+S | 校验 → POST/PATCH → 更新缓存 → toast | 失败保留草稿；版本冲突提示重新加载 |
| 保存并切换 | 编辑器 | 保存成功后设为当前角色，跳到聊天 | 保存失败则不切换 |
| 切换当前角色 | 切换器 / 角色卡“使用” / 聊天头部 | PUT active → 确保唯一会话并返回 `conversationId` → 打开该会话 | 乐观更新，失败回滚；编辑器有脏数据先确认 |
| 新建 | 角色中心 / 切换器 | 打开模板选择 → 新建向导；保存时同事务自动创建唯一会话 | 未保存离开时三选一；不再有手动“新建会话” |
| 复制 | 角色卡“更多” / 官方角色 | POST duplicate → 打开副本编辑器；副本自动获得唯一会话 | 名字冲突自动追加“的副本 2” |
| 归档 | 角色卡“更多” | POST archive → 从切换器/新建列表移除；会话保留 | 当前角色归档时自动切到官方并提示 |
| 清空聊天记录 | 会话行内操作 | POST clear → 逻辑删除消息/记忆，保留会话，重置标题/最后消息时间 | 二次确认，说明不可恢复 |
| 彻底删除 | 归档角色详情 | 二次确认 + 输入角色名 → POST purge | 级联删除该角色唯一会话/消息/记忆/状态/本机立绘；不可恢复 |
| 取消编辑 | 返回 | 有修改时弹“保存并离开 / 放弃修改 / 继续编辑” | 无修改直接返回 |

#### 4.5.1 一对一唯一会话规则

- **唯一性**：`conversations` 增加 `UNIQUE(user_id, character_id)`；服务层所有创建走 `ConversationProvisioner.ensure`，并发冲突由唯一键兜底并回查。
- **自动创建时机**：新建自定义角色、复制角色时在同一事务内创建；官方角色和存量角色在首次 `GET /conversations` 时按用户可见且 active 的角色幂等补建；恢复角色时 ensure。
- **重复创建处理**：`POST /conversations` 为幂等 ensure——已存在返回 200 + 原会话，新建返回 201；不再接受自定义标题。
- **删除处理**：`DELETE /conversations/{id}` 返回 409 `CONVERSATION_DELETE_NOT_ALLOWED`；改为 `POST /conversations/{id}/clear`，只清消息/记忆，会话行保留。
- **切换处理**：`PUT /preferences/active-character` 返回 `conversationId`，前端直接打开，不再调用创建接口。
- **迁移**：V5 先按 `(user_id, character_id)` 合并重复会话（保留最新 active，迁移 messages/memories/activity_events），清理仅 deleted 的组，再加唯一键。

补充规则：

- **保存与切换分离**：编辑器的保存不会自动把角色设为当前；只有“保存并切换”或切换器才会。
- **会话一对一且不可删除**：每个 `(user, character)` 只有一条会话，创建角色/复制角色时自动生成；用户不能手动新建，也不能删除会话，只能清空聊天记录。
- **归档不等于停用**：归档角色从切换器和新建入口消失，但已有唯一会话仍可继续聊，也可恢复；彻底删除才清理数据。
- **删除当前角色**：先自动切到官方沈幼楚，再执行归档/删除，避免当前角色悬空。
- **切换时正在回复**：允许切换；当前轮次在服务端继续，回来时重新拉取消息（沿用现有后台轮次机制）。
- **离线**：角色列表可用本地缓存展示；保存/切换需要服务端，失败时明确提示“当前离线，修改已保留在草稿”。

### 4.6 与现有角色展示的衔接

这是本功能能否“像一个产品”的关键：不能新增一套角色展示，必须把现有展示全部改为角色驱动。

| 现有位置 | 现状 | 改造 |
|---|---|---|
| `App.tsx` | 单一 `avatar` / `portraits` / `heroImage` state；`getAvatar(user.id)` | 引入 `useCharacters` / `CharacterManager`；当前角色 + 角色列表；官方形象读本机覆盖，立绘按 `userId:characterId` 读取 |
| `EmptyChat` | 写死“沈幼楚在这里” | 用当前角色的名字、立绘、介绍 |
| `ChatView.tsx` | 传 `avatar/portraits`；头部、hero、aria、输入框 placeholder、正在输入都写死沈幼楚 | 传 `character`；所有文案用 `character.displayName`；关系状态按 `conversation.characterId` 加载 |
| `ConversationSidebar.tsx` | 所有会话用同一头像；副标题写死“沈幼楚” | 按 `conversation.characterId` 解析头像和名字；增加角色筛选/分组 |
| `CallView.tsx` | aria 写死“与沈幼楚通话” | 用会话角色名与立绘 |
| `LookPage.tsx` | 用户级“形象”页 | 改为“角色”页：角色中心 + 角色编辑器；原形象内容成为“形象”标签 |
| `AvatarEditor.tsx` | 自己持有草稿和保存按钮；标题写死沈幼楚 | 拆成受控的 `AppearancePanel`；草稿与保存由 `CharacterEditor` 统一管理；官方保存到本机覆盖，自定义保存到 PATCH |
| `portraitStorage.ts` | IndexedDB key 为 `userId` | key 改为 `${userId}:${characterId}`；旧 key 迁移到官方角色 |
| `SettingsPanel.tsx` | “清除形象”是用户级；文案说“只保存在本机” | 移除或改为“管理角色”入口；文案改为“自定义角色定义随账号同步；官方角色的本机形象覆盖与立绘只在本机” |
| `api/client.ts` | `getCharacterState()` 无参数 | 增加 `characterId` 参数；新增角色 CRUD/切换 API |
| `PersonaService.java` | 只读 `characters.persona_config` 旧结构 | 增加自定义角色结构化人设编译；边界永远最后追加 |
| `ConversationService.resolveCharacterId` | 接受任意存在的 characterId | 只接受官方或当前用户的自定义角色；新会话拒绝归档角色 |
| `MemoryService.java` | 记忆只按用户查询 | 增加 `character_id`；写入时从会话带入，列表支持按角色筛选，防止跨角色串记忆 |
| `generationConfig.ts` | 默认提示词写死“25 岁、长直黑发、米白针织衫” | 按当前角色的身份 + 形象拼装基础提示词；每个角色可单独保存提示词覆盖（P1） |

衔接原则：

1. **官方角色继续做默认和兜底**。没有当前角色、当前角色失效、删除账号后回到登录页，都回退到沈幼楚。
2. **不复制一套展示组件**。角色卡、聊天头部、会话列表、通话页共用同一个 `CharacterAvatar` / `CharacterName` 数据源。
3. **原有“形象”能力不丢**。捏脸、立绘、随机、模板、立绘生成全部保留，只是从“用户级”下沉到“角色级”。
4. **会话列表不做成“每个角色一个列表”**。用顶部角色切换器 + “当前角色 / 全部”筛选，既清晰又不会让用户找不到旧会话。
5. **记忆页必须显示角色**。多条记忆混在一起会让人误以为“她记得我对别人说过的话”；默认按当前角色筛选，可切“全部”。
6. **会话唯一，不再手动新建**。每个用户对同一角色只有一条会话；角色创建/复制时自动创建，官方/存量角色首次拉取列表时幂等补建；前端移除“新建会话”入口。

### 4.7 界面细节与无障碍

- **最小窗口 1280×800**：编辑器左预览 340px + 右表单自适应；125% 缩放不出现横向滚动。
- **窄宽度**：预览折叠为顶部 96px 高的横向角色卡，随滚动吸顶；不隐藏预览。
- **键盘**：Tab 顺序为“标签 → 选项 → 细调 → 底部操作”；Ctrl/Cmd+S 保存；Esc 关闭切换器/确认框；标签页支持左右方向键。
- **焦点**：打开编辑器聚焦标题；关闭后回到来源角色卡；删除确认框默认焦点在“取消”。
- **色彩**：色卡带文字标签和选中勾；不仅靠颜色传达状态；正文对比度 ≥ 4.5:1。
- **动效**：仅用于切换/保存反馈，120–180ms；尊重 `prefers-reduced-motion`。
- **加载/错误/空态**：每页都有三态；不用浏览器 `alert` 承载业务错误。
- **文案**：统一用“她/角色/女友”，不用“AI 模型/提示词/参数”等实现词；编辑器里不出现 JSON、枚举 ID。

## 5. 数据与接口设计

### 5.1 数据模型

复用现有 `characters` 表，增加“归属、形象、状态、版本”字段，避免另起一张表后还要把会话/状态表改成多态引用。

```sql
-- V4__character_customization.sql / V5__one_conversation_per_character.sql（提案）
-- 会话唯一键与重复数据合并位于 V5；其余字段位于 V4。
ALTER TABLE characters
    ADD COLUMN owner_user_id BIGINT NULL AFTER id,
    ADD COLUMN source_character_id BIGINT NULL AFTER owner_user_id,
    ADD COLUMN avatar_config JSON NULL AFTER persona_config,
    ADD COLUMN status VARCHAR(20) NOT NULL DEFAULT 'active' AFTER is_public,
    ADD COLUMN version BIGINT NOT NULL DEFAULT 0 AFTER status,
    ADD INDEX idx_characters_owner_status (owner_user_id, status),
    ADD UNIQUE KEY uk_characters_owner_name (owner_user_id, display_name),
    ADD CONSTRAINT fk_characters_owner FOREIGN KEY (owner_user_id) REFERENCES users (id);

CREATE TABLE user_preferences (
    user_id             BIGINT      NOT NULL,
    active_character_id BIGINT      NULL,
    created_at          DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at          DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (user_id),
    CONSTRAINT fk_user_preferences_user FOREIGN KEY (user_id) REFERENCES users (id),
    CONSTRAINT fk_user_preferences_character FOREIGN KEY (active_character_id)
        REFERENCES characters (id) ON DELETE SET NULL
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;

ALTER TABLE conversations
    ADD UNIQUE KEY uk_conversations_user_character (user_id, character_id),
    ADD INDEX idx_conversations_user_character_last (user_id, character_id, last_message_at);

ALTER TABLE memories
    ADD COLUMN character_id BIGINT NULL AFTER user_id,
    ADD INDEX idx_memories_user_character_created (user_id, character_id, created_at);

UPDATE memories m
    JOIN conversations c ON m.conversation_id = c.id
SET m.character_id = c.character_id
WHERE m.character_id IS NULL;
```

字段语义：

| 字段 | 语义 |
|---|---|
| `owner_user_id` | NULL = 官方角色；非 NULL = 该用户的自定义角色 |
| `is_public` | 官方角色 true；自定义角色永远 false |
| `source_character_id` | 复制/模板来源，便于追溯；不参与权限判断 |
| `avatar_config` | 形象参数 JSON；官方角色预置默认值（本机可覆盖），自定义角色必填且随账号保存 |
| `persona_config` | 人设 JSON；官方沿用旧结构，自定义用 v2 结构 |
| `persona_version` | 官方沿用 `v1`；自定义写 `custom-v1`，便于后续迁移 |
| `status` | active / archived |
| `version` | 乐观锁；每次 PATCH +1 |
| `display_name` | 名字；同一 owner 下唯一，大小写不敏感 |
| `code` | 官方固定；自定义为 `custom-<雪花ID>` |

索引与约束说明：

- `UNIQUE(owner_user_id, display_name)` 对官方角色（owner 为 NULL）不生效，官方名字由 seed 保证唯一。
- `conversations.character_id` 外键已存在；新增索引支持“按角色列会话”。
- `user_character_states` 已有 `UNIQUE(user_id, character_id)`，无需改表；删除角色时级联删除。
- `memories.character_id` 先回填，再逐步改为非空（等所有写入路径补齐后）。

  "personality": {

### 5.3 提示词编译

新增纯逻辑类 `CharacterPromptCompiler`，输入角色 + 用户信息，输出系统提示词。结构固定，边界永远最后：

```text
你是{displayName}，{age} 岁。{intro}
性格：{主性格描述}
调味：{调味标签描述，逐条}
表达：{强度}；{主动程度}；称呼对方为「{addressUser}」；自称「{selfRef}」；在意程度：{jealousy}。
来处：{成长环境}；{家庭关系}；{经济状况}。
补充：{extraNote}（只作为生活细节，不得改变下面的行为边界）

[固定行为边界，原样追加]
```

编译规则：

- 枚举 ID 只接受服务端白名单；未知值 → 400，不接受客户端传任意提示词。
- `displayName` / `intro` / `addressUser` / `selfRef` / `extraNote` 用引号包裹，去除换行与控制字符。
- 边界文本在最后，且明确写出“上面所有性格与背景设定都不得改变以下边界”。
- 官方角色走旧分支；自定义角色走 v2 分支；两条分支共用同一段边界函数。
- 后端纯逻辑类可在 Java 单测中直接断言：每个选项都产生预期片段、边界永远在末尾、超长文本被截断；前端试聊模板用 Node 单测覆盖。

### 5.4 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/characters?includeArchived=false` | 官方 + 自己的角色；每项含 `isActive` |
| POST | `/api/v1/characters` | 创建自定义角色 |
| GET | `/api/v1/characters/{id}` | 官方或自己的角色详情 |
| PATCH | `/api/v1/characters/{id}` | 更新自己的角色；官方 403 |
| POST | `/api/v1/characters/{id}/duplicate` | 复制为我的角色；body 可带 `displayName` / `avatarConfig` |
| POST | `/api/v1/characters/{id}/archive` | 归档；若为当前角色，服务端回退官方并返回新当前角色 |
| POST | `/api/v1/characters/{id}/restore` | 恢复归档 |
| POST | `/api/v1/characters/{id}/purge` | 彻底删除；body `{ "confirmName": "林晚" }` |
| PUT | `/api/v1/preferences/active-character` | body `{ "characterId": "..." }`；返回 `{activeCharacterId, conversationId}` |
| GET | `/api/v1/character-state?characterId=...` | 不传则用当前角色，兼容旧调用 |
| GET | `/api/v1/conversations?characterId=...` | 查询前按角色 ensure；每个角色最多一条 |
| POST | `/api/v1/conversations` | 幂等 ensure：已存在 200 + 原会话，新建 201；title 已废弃；归档角色 409 |
| POST | `/api/v1/conversations/{id}/clear` | 清空聊天记录，保留会话；204 |
| DELETE | `/api/v1/conversations/{id}` | 不允许删除，409 `CONVERSATION_DELETE_NOT_ALLOWED` |
| GET | `/api/v1/memories?characterId=...` | 可选按角色筛选（P1） |

`CharacterView`：

官方角色的 `avatarConfig` 是官方默认值；前端展示时优先使用本机覆盖（若存在），保存官方形象不写服务端。自定义角色的 `avatarConfig` 才是账号级数据。

请求/响应约束：

- 创建和更新只接受结构化字段，不接受 `systemPrompt`、`personaPrompt`、`rawConfig` 等自由提示词字段。
- `GET /characters` 的查询条件是 `is_public = true OR owner_user_id = 当前用户`；官方角色不受 `includeArchived` 影响，归档只作用于自定义角色。
- `PUT /preferences/active-character` 只接受官方或本人所有、且 `status='active'` 的角色；归档角色返回 409。
- `PATCH` 必须带 `version`；服务端 `UPDATE ... WHERE version = ?`，影响行数为 0 返回 409。
- 官方角色的 `PATCH` 返回 403 `CHARACTER_READONLY`；读取他人自定义角色统一返回 404，避免泄露存在性。
- `duplicate` 复制人设与形象，不复制本机立绘；body 可带 `avatarConfig`，用于把官方角色的本机形象覆盖带入副本；前端可选“同时复制立绘”。
- `purge` 校验 `confirmName` 与角色名一致，避免误删；若删除的是当前角色，事务内回退官方并在响应中返回新的 `activeCharacterId`。

### 5.5 错误码

| HTTP | code | 场景 |
|---|---|---|
| 400 | `CHARACTER_NAME_INVALID` | 名字长度/字符不合法 |
| 400 | `CHARACTER_AGE_OUT_OF_RANGE` | 年龄 < 18 或 > 45 |
| 400 | `CHARACTER_OPTION_INVALID` | 枚举值不在白名单 |
| 400 | `CHARACTER_NOTE_TOO_LONG` | 补充设定超长 |
| 403 | `CHARACTER_READONLY` | 修改官方角色 |
| 404 | `CHARACTER_NOT_FOUND` | 不存在或不属于当前用户 |
| 409 | `CHARACTER_NAME_TAKEN` | 同用户重名 |
| 409 | `CHARACTER_LIMIT_REACHED` | 超过 12 个 |
| 409 | `CHARACTER_VERSION_CONFLICT` | 并发保存 |
| 409 | `CHARACTER_ARCHIVED` | 用归档角色开新会话 |
| 409 | `CHARACTER_CONFIRM_MISMATCH` | 彻底删除确认名不一致 |

### 5.6 迁移方案

1. **角色表**：官方沈幼楚补 `avatar_config` 默认值；`owner_user_id` 保持 NULL；`status='active'`；`version=0`。
2. **当前角色**：为每个已有用户写入 `active_character_id = 沈幼楚`；没有偏好记录时读取也回退官方。
3. **会话**：V5 按 `(user_id, character_id)` 合并重复会话、迁移 messages/memories/activity_events，清理仅 deleted 的组，再加唯一键；存量角色缺会话时由首次 `GET /conversations` 幂等补建。
4. **记忆**：按 `conversation_id` 回填 `character_id`；回填失败的记录保持 NULL，列表按“未知角色”展示，不阻塞。
5. **捏脸**：读取旧 key `shenyouchu.avatar.v1.<userId>`，将其作为官方角色的**本机形象覆盖**（新 key 可用 `shenyouchu.official-avatar.v1.<userId>`，也可以直接沿用旧 key）。旧会话继续使用这个形象，不换脸。
   - 首次进入角色页给一次性说明：“你之前为沈幼楚调整过形象，已保留在本机。想连人设一起改，可以复制为我的角色。”
   - 动作为 [知道了] [复制为我的角色]；不强制选择，默认保留本机覆盖。
   - 复制时把当前形象（含本机覆盖）写入新角色；旧会话是否迁移由用户勾选，默认不迁移。
   - 清除本机覆盖的入口在角色页 → 形象，清除后回到官方默认形象。
6. **立绘**：旧 IndexedDB key 是 `userId`。首次读取时若存在旧记录，复制到 `${userId}:${officialCharacterId}`，成功后删除旧 key；失败则保留旧 key，界面仍能显示。
7. **设置文案**：删除“形象只保存在本机”的笼统表述；改为“自定义角色定义随账号同步；官方角色的本机形象覆盖与立绘只在本机”。
8. **删除账号**：级联清理 `characters`（自定义）、`user_preferences`、`conversations`、`memories`、`user_character_states`、官方本机形象覆盖与本机立绘；官方角色不动。同步更新删除账号确认文案，明确包含“自定义角色”。

### 5.7 安全与隐私

- 所有角色接口都从认证上下文取 `userId`，不接受客户端传入的 owner。
- 读取/修改/删除他人自定义角色一律 404；官方角色写操作 403。
- 新会话 ensure 时校验 `character` 为官方或本人所有，且 `status='active'`；归档角色只能继续已有会话。
- `GET /character-state` 的 `characterId` 同样只接受官方或本人所有，防止通过状态接口探测他人角色。
- 提示词只由服务端编译；客户端不能提交系统提示词或模型参数。
- 自由文本字段限长、去换行、引号包裹；边界文本最后追加。
- 角色设定属于用户私密数据：不进入用户搜索索引，不进入运营检索结果；活动事件只记 `characterId` 与事件类型，不记人设正文。
- 立绘只在本机；如果后续上云，必须走私有对象存储 + 短期签名 URL，并纳入删除矩阵。
- 角色删除纳入删除矩阵：自定义角色 → 会话 → 消息/记忆/关系状态/本机立绘；归档不触发级联。

## 6. 关键流程

### 6.1 创建一个角色

```text
角色中心 → 新建 → 选模板/空白 → 填名字年龄 → 调形象 → 选性格 → 选家庭
→ 保存并创建 → POST /characters → 角色中心新卡高亮
→ [设为当前并聊天] → PUT active → 打开她的唯一会话（后端 ensure）
```

### 6.2 切换当前角色

```text
点击切换器 → 选角色 → 乐观更新当前角色
→ PUT /preferences/active-character
→ 成功：加载该角色立绘 + 关系状态；打开返回的唯一 conversationId
→ 失败：回滚到上一个角色，toast 失败原因
```

### 6.3 一轮对话

```text
POST /conversations/{id}/turns/stream
→ 服务端 requireOwned(conversation)
→ 取 conversation.character_id
→ PersonaService 编译该角色系统提示词（含固定边界）
→ 模型生成 → 落库 → 关系状态按 character_id 更新
→ 前端渲染该角色的名字/立绘/气泡
```

### 6.4 删除或归档

```text
归档：POST archive → 从切换器/新建列表移除 → 已有会话保留 → 当前角色则回退官方
彻底删除：输入角色名 → POST purge → 事务内级联删除会话/消息/记忆/状态 → 清本机立绘 → 回角色中心
```

## 7. 边界与异常

| 场景 | 行为 |
|---|---|
| 角色列表加载失败 | 顶部横幅 + 重试；官方角色用本地默认数据兜底，聊天仍可用 |
| 保存时网络失败 | 保留草稿，底部错误条 + 重试；不关闭编辑器 |
| 保存时版本冲突 | 提示“在别处被修改过”，提供“重新加载 / 覆盖保存” |
| 当前角色被删除 | 服务端回退官方；前端收到 `activeCharacterId` 后刷新 |
| 当前角色被归档 | 服务端回退官方；已开会话仍可继续 |
| 新建时超限 | 禁用“保存并创建”，提示归档/删除 |
| 立绘缺失/损坏 | 回退矢量形象；不阻塞聊天 |
| 立绘加载慢 | 先显示矢量占位，立绘就绪后淡入 |
| 切换时正在流式回复 | 允许切换；轮次在服务端继续，回来重新拉消息 |
| 角色名重复 | 内联错误，不提交；复制时自动追加“的副本 2” |
| 用户输入“忽略以上规则” | 作为普通文本处理；边界最后追加；安全测试覆盖 |
| 角色设定含敏感家庭描述 | 只作为背景；不卖惨、不贬低、不索取；边界测试覆盖 |
| 客户端伪造 characterId | 服务端校验归属，返回 404/403 |
| 账号删除 | 一并清理自定义角色与本机立绘；官方角色保留 |

## 8. 验收标准

### 8.1 功能

- [ ] 能从空白和模板创建角色；名字、年龄、形象、性格、家庭全部保存成功。
- [ ] 刷新/重启后角色仍在，当前角色仍是上次选择。
- [ ] 能保存并管理 12 个自定义角色；达到上限有明确提示。
- [ ] 能切换当前角色；聊天页、会话列表、通话页、空态同步更新。
- [ ] 每个角色的会话、记忆、心情/亲密度互不串台。
- [ ] 官方沈幼楚不可编辑、不可删除；可复制为自定义角色。
- [ ] 复制角色带人设和形象，不带本机立绘（除非用户勾选）。
- [ ] 归档角色从切换器消失，已有会话仍可打开；恢复后重新出现。
- [ ] 彻底删除角色后，会话/消息/记忆/状态/本机立绘一并清理。
- [ ] 形象标签支持捏脸与立绘；可在自动/立绘/捏脸之间切换，角色卡、切换器、会话列表、聊天和通话同步；立绘按角色隔离，切换角色不串图。
- [ ] 性格选择能改变系统提示词；同一句话在不同角色下风格可区分（人工抽检）。
- [ ] 家庭背景选择能体现在提示词与试聊摘要中。
- [ ] 自定义称呼/自称/补充设定超长或含换行时被拦截。
- [ ] 旧版捏脸触发一次性迁移提示；旧立绘迁移到官方角色。
- [ ] 旧会话、旧关系状态、旧记忆不受影响。

### 8.2 体验

- [ ] 从模板到保存，默认路径 ≤ 3 分钟、≤ 12 次点击。
- [ ] 任意页面切换角色 ≤ 2 次点击。
- [ ] 编辑器任意时刻能看到实时预览；切换标签不丢草稿。
- [ ] 有未保存修改时离开，必定出现“保存/放弃/继续”三选一。
- [ ] 所有选项有文字标签，不依赖颜色；键盘可完成创建与保存。
- [ ] 1280×800 和 125% 缩放下无横向滚动、无遮挡。
- [ ] 加载/空/错误三态齐全；错误文案可行动。
- [ ] 性格试聊示例即时更新，且标注“实际对话由模型生成”。

### 8.3 安全与隔离

- [ ] A 无法读取/修改/删除 B 的自定义角色（404）。
- [ ] A 无法用 B 的 characterId 创建会话或读取其唯一会话。
- [ ] 官方角色写操作返回 403。
- [ ] 客户端提交任意系统提示词字段被拒绝（DTO 不接收该字段）。
- [ ] 所有角色提示词都包含固定边界，且边界在最后。
- [ ] 年龄 < 18 无法保存。
- [ ] 角色设定不出现在运营检索结果中。
- [ ] 删除账号后自定义角色与本机立绘被清理。

### 8.4 回归

- [ ] 单角色用户仍默认使用沈幼楚，聊天/语音/通话/记忆/设置可用。
- [ ] 现有会话、消息、记忆、关系状态数据不丢。
- [ ] 现有捏脸预设、随机、恢复默认仍可用。
- [ ] 现有立绘导入、生成、清除仍可用，只是作用域变为当前角色。

6. **补迁移与删除**：旧捏脸/立绘迁移、归档/彻底删除、删除账号级联。

这个顺序保证每一步都能独立回归，不会出现“角色功能做完，聊天坏了”的大爆炸。
