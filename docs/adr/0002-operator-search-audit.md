# 跨用户运营检索采用受控审计模式

- 状态：accepted
- 关联：FR-8.5 / FR-8.6、NFR-10

产品确认同时支持两类搜索：

1. 用户搜索自己的消息、记忆、活动摘要与录像元数据；
2. 运营人员跨用户检索，用于问题排查与安全处置。

这直接改变了此前"不设计管理员浏览用户私密对话"的原则。完全禁止会让线上问题无法定位；无条件开放则会让 AI 伴侣的高敏感内容处于任意浏览状态，两者都不可接受。因此决定采用**受控运营检索**：跨用户搜索是能力，但被角色、事由、脱敏和审计四重约束，而不是默认权限。

决策内容：

- `operator` 为独立角色，最小权限，经审批授予并可随时撤销；
- 每次检索必须提交事由，服务端校验角色与事由后才执行；
- 默认只返回脱敏摘要与元数据，展示完整正文需单独授权并额外留痕；
- 每次检索写入 `admin.search.performed` 活动事件，记录操作者、事由、查询哈希（不存明文查询词）、筛选范围、命中文档类型与数量、时间；
- 禁止批量导出正文、禁止下载他人录像、禁止修改用户数据；
- 用户端搜索与运营检索使用不同接口与权限路径，共用同一个 `SearchPort`。

后果：

- 隔离测试必须覆盖"operator 无事由/越权范围被拒绝"和"每次检索都有审计"；
- 运营检索上线前需要先完成角色管理与脱敏策略，属于 P2，不阻塞 P1 用户搜索；
- 若未来需要把内容用于模型训练或分析，属于新的用途，必须重新评审，不因本决策自动获得授权。
